# JSONSQLite v1.5.0 功能测试计划

> 用例前缀：`FT-V15-*`  
> 实现落点建议：`packages/core/test/v1.5-*.test.ts`、`apps/bench`

---

## 1. Rekey

| ID | 场景 | 期望 |
|----|------|------|
| FT-V15-KEY-01 | rekey 到新路径 | 新库用新钥可读；旧库旧钥仍可读（未删时） |
| FT-V15-KEY-02 | 错误旧钥 | 失败，staging 不残留半成品或可清理 |
| FT-V15-KEY-03 | inplace + --yes | 成功后仅新钥可打开 |
| FT-V15-KEY-04 | rekey 中断恢复 | journal 存在时 reopen/续跑或安全回滚 |
| FT-V15-KEY-05 | CLI rekey 非 TTY | exit 0；`--yes` 行为符合文档 |

## 2. 性能 / Lazy load

| ID | 场景 | 期望 |
|----|------|------|
| FT-V15-PERF-01 | lazy open | open 后未访问的集合文件可不驻留内存（或 metrics 显示未加载） |
| FT-V15-PERF-02 | 首次访问加载 | 第一次 query 成功；再次访问无重复全量 I/O 异常 |
| FT-V15-PERF-03 | prefetch | `prefetchCollections` 预热后 metrics 反映已加载 |
| FT-V15-PERF-04 | bench 冒烟 | 约定数据量下 insert/query/JOIN 完成且记录耗时 |

## 3. 运维

| ID | 场景 | 期望 |
|----|------|------|
| FT-V15-OPS-01 | vacuum 单表 | 文档数不变；文件体积合理下降（删大量后） |
| FT-V15-OPS-02 | vacuum 全库 | 所有表一致；WAL 截断 |
| FT-V15-OPS-03 | doctor --deep healthy | exit 0；JSON 含检查项 |
| FT-V15-OPS-04 | doctor --deep 人为损坏 | 检测到并 exit ≠ 0 |
| FT-V15-OPS-05 | CLI 非交互 | vacuum/doctor 无需 TTY |

## 4. SQL 小增强

| ID | 场景 | 期望 |
|----|------|------|
| FT-V15-SQL-01 | `NOT LIKE` | 与 LIKE 互补 |
| FT-V15-SQL-02 | `SELECT COUNT(*)` | 数值正确；与 `count()` API 一致 |
| FT-V15-SQL-03 | 非法 SQL ErrorCode | 均为稳定枚举，非裸 Error |
