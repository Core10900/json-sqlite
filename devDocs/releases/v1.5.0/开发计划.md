# JSONSQLite v1.5.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**生产就绪冲刺（LTS 前夜）**  
> 前置假设：`1.4.0` 已交付主存储加密、LIKE/JOIN、export/import、`queryCursor`、Admin 鉴权收紧  
> 后继：`1.5.5` 专攻 CLI LTS 化 → `1.6.0` 正式标为 **长期稳定（LTS）** 并冻结公开 API 文档

---

## 1. 背景与目标

版本线现状（规划视角）：

```text
1.2  表管理 + SQL 子集
1.3  硬化：耐久 / DDL journal / 诚实 API          ✅ 已发布
1.4  加密主存 + LIKE/JOIN + 导入导出/游标         📋 已规划
1.5  生产就绪：rekey、性能、压测、运维工具         ← 本文
1.5.5 CLI LTS 化：常用命令扩展 + 交互/脚本契约   → 见 v1.5.5
1.6  LTS：API 冻结 + 根目录完整文档 + 支持策略     → 见 v1.6.0
2.0  破坏性：多写者 / 默认硬 Schema / 存储大变
```

**1.5.0 要解决的问题**：1.4 把「能用的能力」补齐后，距离「敢长期 pin」还差：

1. 加密库 **密钥轮换** 有可执行路径（非仅文档口述）
2. 大表场景下的 **启动/查询性能** 可测、可优化、有回归基准
3. **运维闭环**：压缩/校验/诊断命令可脚本化
4. **质量门槛**：压测 + 模糊/属性测试 + 破坏性故障注入覆盖 1.3–1.4 关键路径
5. 为 1.6 LTS **冻结清单** 做准备（弃用项清零或打标）

**1.5 不做**（留给 1.6 文档冻结或 2.0）：

- 宣称 LTS / 多年支持窗口（1.6 宣布）
- 多写者、Raft、列存、默认 `schemaMode: 'strict'`
- 三表及以上 JOIN、子查询、窗口函数

### 1.5 成功标准

1. 提供 **离线 rekey**（CLI + 库 API）：旧钥读出 → 新钥写入新目录或原地安全替换
2. 集合 **lazy load** 可配置；冷启动大库耗时可观测
3. `vacuum` / `doctor --deep` / 校验 checksum 工具可用
4. Bench 与 FT-V15 压测套件合入 CI（阈值或 nightly 可接受）
5. 公开 API 弃用清单落入 CHANGELOG；无未文档化的「偷偷行为」
6. 发版 `1.5.0`，并输出《1.6 LTS 准入检查表》草稿（可放在 `devDocs/releases/v1.6.0/`）

## 4. 技术方案要点

### 4.1 Rekey

```text
open(oldKey) → export 逻辑复用或流式读行
→ 写 staging(storagePath + '.rekey-tmp') with newKey
→ fsync + journal { op:'rekey', phase }
→ 原子替换目录（或用户指定 --out 新路径，更安全默认）
```

**推荐默认**：`rekey` **写出到新路径**（`--out`），避免原地风险；原地替换需 `--in-place --yes`。

### 4.2 Lazy load

- `open` 只 load catalog + indexes 元数据
- 首次 `query`/`insert`/`run` 触及集合时 `loadCollection`
- 兼容：提供 `prefetchCollections?: string[]` 预热

### 4.3 Vacuum

- 重写 `data.jsonl`（仅存活文档）
- `wal.truncate` + 可选压缩 deltas（若与时间旅行冲突需文档说明保留策略）

### 4.4 COUNT(*)

```sql
SELECT COUNT(*) FROM users WHERE age > 18
```

映射为 `count(collection, filter)`，`SqlResult` 可用 `{ type:'rows', rows:[{ count: N }], ... }` 或扩展 `type:'scalar'`——**在 1.5 定一种并写入 1.6 冻结文档**。
