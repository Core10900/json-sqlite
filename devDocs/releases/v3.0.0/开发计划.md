# JSONSQLite v3.0.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**异步复制雏形**  
> 前置：**LTS-2（2.2）** 已是单机生产 pin；多写者契约以 **LTS-3（2.5）** 为准。复制建立在已经能恢复的单机之上  
> **LTS：否**。本版也**不是**设计完工版  
> 兼容：**MAJOR**（复制日志格式）。单机默认模式必须仍能打开 2.5 库；不开启复制时行为与 LTS-3 默认单写者一致  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)

---

## 1. 背景

方案 Phase 5 的验收是异步主从 demo，加上列存相对文档模式的可测加速。列存已放在 2.3。本版只做复制雏形，把选主和自动分片留在 3.4，并且 3.4 首发不能当 LTS。

生产级数据库的高可用如果做不到手动可恢复，就不要做成「看起来会自动选主」。

---

## 2. 目标

1. 复制默认关闭。关闭时回归 LTS-3 的单机测试。  
2. 开启后：一个主、一个或多个从；主的已提交写入最终在从库可见。  
3. 从库滞后可在 metrics 与 `doctor` 中读到。  
4. 主宕机：**不**自动选主。文档与测试断言从库停在已复制的前缀，由运维按手册处理。  
5. 分片路由可以有 hash/range 的实验开关，默认关。实验开关失败不阻塞 3.0 发版；未实现则不要出现在稳定 CLI 里。  
6. 提供 2.5 → 3.0 的单机迁移。开启复制不是迁移的必选项。

### 成功标准

- 两节点最终可见有自动化测试。  
- 杀死主进程后，从库不接受写入冒充新主（除非用户按文档把从库提升，且该步骤是显式命令）。  
- FT-V30-* 全绿。Release 标题含 **非 LTS**，不含 Vision Complete。

### 不做

Raft、自动 rebalance、跨机锁、Quorum 写成功条件、GraphQL、WASM。Quorum 与读写分离在 **3.1**。复制生产 pin 是 **3.2（LTS-4）**。

## 5. 风险

| 风险 | 缓解 |
|------|------|
| 复制半成品被当成高可用 | 命令与文档禁止 failover 字样，除非该步骤是手动 promote |
| 分片原型拖住发版 | 默认关，可整段移出 3.0 |
