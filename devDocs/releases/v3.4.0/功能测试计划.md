# JSONSQLite v3.4.0 功能测试计划

> 前缀：`FT-V34-*`  
> **非 LTS**。复制关闭且不加载适配器时，必须回归 3.3 的单机路径。

## 0. 门禁

| ID | 场景 | 期望 |
|----|------|------|
| FT-V34-REG-01 | 复制关、无适配器 | 3.3 单机回归绿 |
| FT-V34-VER-01 | version | `3.4.0`，`lts: false` |
| FT-V34-CLI-01 | 稳定帮助 | 无 `cluster`，无 failover |

## 1. 复制硬化

| ID | 场景 | 期望 |
|----|------|------|
| FT-V34-QUO-01 | 确认数不足 | 写入失败，错误码稳定，可重试；status 不是已复制 |
| FT-V34-ROUTE-01 | 读请求 | 到达从库；写请求不到从库 |
| FT-V34-ROUTE-02 | 滞后超阈值 | 默认策略与另一种策略都有断言 |
| FT-V34-S3-01 | 冷存储写后读 | 读回同一文档 |
| FT-V34-S3-02 | 对象存储失败 | 热文档点查成功；未取回的冷文档不出现在热结果 |
| FT-V34-AUD-01 | promote | 审计含操作者、时间、角色变化 |
| FT-V34-DOC-01 | 三节点清单 | 测试名或检查清单能按 README 步骤复述 |

## 2. 接入层

| ID | 场景 | 期望 |
|----|------|------|
| FT-V34-GQL-01 | GraphQL 查询 | 与库 API 同一组文档 |
| FT-V34-GQL-02 | GraphQL 变更 | 与库 API 写后的文档一致 |
| FT-V34-POOL-01 | close | 再次使用得到文档化的错误；无残留文件锁 |
| FT-V34-MDB-01 | 两个 storagePath | A 的写入在 B 中不可见 |
| FT-V34-MDB-02 | 关闭 A | B 仍可查询 |
| FT-V34-FW-01 | Express 示例 | 写一次再读回 |
| FT-V34-FW-02 | Nest 示例 | 写一次再读回 |
| FT-V34-AI-01 | 无 provider | 返回规则建议，安装不拉取 LLM |
| FT-V34-AI-02 | provider 抛错 | 原查询成功 |
| FT-V34-VEC-01 | 小样本向量查询 | 命中非 stub 的空数组，含分数 |
| FT-V34-SRV-01 | `serve` 与 `db.serve()` | 只提供已有 HTTP 路由；与 `startServer()` 的路径一致 |
| FT-V34-API-01 | `collection` 与 `table` | 写入后用另一句柄能读回 |
| FT-V34-REST-01 | REST 插入后按 `_id` 读取 | 与引擎 `insert` 后的文档一致 |
| FT-V34-REST-02 | REST 删除后再读 | 文档化的未找到；`POST /query` 仍可用 |
| FT-V34-CFG-01 | `config validate` | 接受默认关闭的 `graphql`；拒绝 `cluster` |

## 放行

1. REG、QUO、ROUTE、S3、GQL、POOL、MDB、VEC 全绿。  
2. 核心包把 Express、Nest 或 LLM SDK 写成 dependency / peerDependency，不得发版。
