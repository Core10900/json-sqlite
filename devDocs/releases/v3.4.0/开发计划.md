# JSONSQLite v3.4.0 开发计划

> 包名：核心仍 `@webofcat/jsonsqlite`；GraphQL、示例和向量插件可拆包  
> 主题：**复制硬化与接入层**  
> 前置：**3.3.0** 异步复制雏形已绿。两条工作流互不阻塞实现，但本版两个都要验收  
> **LTS：否**  
> 兼容：相对 3.3 为 **MINOR**。不开启复制、不加载适配器时，单机契约不变  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)  
> npm 标签与发布后核对：[发布说明.md](./发布说明.md)

## 1. 目标

### 工作流 A — 复制硬化

1. Quorum 可配置。达不到确认数时写入失败，错误码稳定，调用方可重试。主库不把未确认写入报告为已复制。  
2. 读请求可路由到从库，写只到主。从库滞后超过阈值时，策略是失败或退回主，默认写进 README，两种都能测。  
3. 三节点手册：启动、看滞后、停一个从、手动提升。步骤与测试或检查清单一致。  
4. S3（或等价对象存储）冷存储从 2.3 的 stub 变为可读写示例。当前代码里 stub 的 `availableIn` 仍是 `3.1`，本版改为 `3.4`，并同步 README 与测试。插件或对象存储失败时，热数据仍可点查。冷层上尚未取回的数据不能按热层返回。  
5. 仍然没有自动选主。`replica promote` 写入审计：操作者、时间、角色变化。

### 工作流 B — 接入层

1. GraphQL：查询和变更映射到现有 JSON API。可以是子包。不承诺完整 GraphQL 数据库。  
2. 连接池：同进程借出、归还、`close`。close 之后没有泄漏的文件锁或句柄。  
3. 多数据库注册表：至少两个 `storagePath`。读 A 看不到 B 的写入，关掉 A 不影响 B。  
4. Express 与 Nest 示例（或独立包）各完成一次写入再读回。核心包不 peer 依赖这两个框架。  
5. `advisorProvider` 可选。未配置时仍是规则引擎，安装包不依赖外部 LLM。provider 失败不得让查询失败。  
6. 向量插件的可用实现：能建索引、按向量查询、返回距离或分数。文档写明这不是通用向量库，并写小样本边界。当前 stub 的 `availableIn` 是 `3.3`，本版改为 `3.4`。与 2.3 stub 的差别是本版返回真实命中。  
7. `jsonsqlite serve` 把现有 HTTP/Admin 跑成常驻进程。库方法 `db.serve()` 与现有 `startServer()` 行为相同。`open()` 不因配置自动监听端口。不新增线协议。  
8. `db.collection(name)` 与 `db.table(name)` 返回同一类句柄，`insert` / `find` / `update` / `delete` 委托现有引擎方法，不另建一套存储。  
9. 包若拆分，先改《JSONSQLite npm包与后端接入说明》的 publish 边界，再写安装命令。  
10. 本版实现的 `graphql` 配置进入 example 且默认关闭，移出危险键。`cluster` 与 `wasm` 仍拒绝，留到 3.5。  
11. **REST 文档接口**：在现有鉴权下提供按集合的写入、按 `_id` 读取、更新和删除，全部委托现有引擎方法。`POST /query` 保留。不另做一套查询语言，也不改存储。

### 成功标准

- 不开启复制、不加载适配器时，3.3 的单机回归绿。  
- Quorum 不足的写入失败，且 status 不把它标成已复制。  
- 冷存储故障后的热集合点查成功。  
- GraphQL 的一次查询和一次变更与库 API 结果一致。  
- FT-V34-* 全绿。Release 标明 **非 LTS**。

### 不做

Raft、自动分片、自动选主、跨机锁、WASM、多语言 TCP。这些在 **3.5**。WASM 的只读实验包在 3.5 必交付，写路径不进 3.6 的承诺。冻结在 **3.6**。

## 3. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。只改版本号、把手动提升写成自动选主、或把向量写成通用向量库，都不算完成。

写作要求：

- 说明文字用中文。本版改到的 `packages/core/README.md` 与仓库根 `README.md` 都用中文写。命令、配置键、错误码和代码示例保持原文。用英文段落代替中文说明不算完成。
- 与已测错误码、滞后策略、审计、包边界一致。不加载适配器时，单机与 3.3 的复制关闭路径仍然成立。
- 每个新能力都有可复制示例：安装（若在子包）、最小调用、关闭、失败时的结果。
- 文首写明 **3.4.0、非 LTS**。仍然没有自动选主。

本版 README 必须写清：

1. Quorum 的配置名和默认值。达不到确认数时的稳定错误码、能否重试。失败时 status 的哪个字段不是「已复制」。
2. 读如何路由到从库，写为什么只到主。滞后超阈值的默认策略是失败还是退回主，如何改，两种策略下调用方看到什么。
3. 三节点手册摘要：启动、看滞后、停一个从、手动提升。每步的命令、预期输出、失败时停止。promote 的审计字段。没有自动选主。
4. 冷存储：注册、配置、写入、读回。对象存储失败后的热文档点查示例。尚未取回的冷文档不能出现在热层结果里。
5. GraphQL：一条查询、一条变更，以及如何对照库 API。写明不支持的操作范围。包名和入口若在子包，给出 `npm install`。
6. 连接池：借出、归还、`close` 的示例。close 之后再使用的结果。写明没有泄漏的锁。
7. 多库：两个 `storagePath` 的 `db list|register|use|unregister`。读 A 看不到 B。关掉 A 之后 B 仍可查询。
8. Express 与 Nest：仓库路径或包名、启动命令、一次写入再读回。核心 `package.json` 不把这两个框架列为 dependency 或 peerDependency。
9. 未配置 `advisorProvider` 时返回规则建议。配置后的注入方式。provider 抛错时原查询仍成功。
10. 向量：建索引、一条查询、分数字段的含义、适合的样本量、不保证的过滤或实时性。写明不是通用向量库，也不是 2.3 的空 stub。
11. `serve` 的命令和它监听的现有 HTTP 端口。`db.serve()` 与 `startServer()` 的等价示例。写明没有新的 TCP 协议。  
12. `collection` / `table` 的一条写入和一条查询，结果与直接调用引擎方法相同。  
13. REST：插入、按 `_id` 读取、更新、删除的路径和鉴权，与 `/query` 相同。写明这些调用等价于哪一个引擎方法。  
14. 明确不在本版：Raft、自动分片、自动选主、跨机锁、WASM。`config validate` 仍拒绝 `cluster` 与 `wasm`。
