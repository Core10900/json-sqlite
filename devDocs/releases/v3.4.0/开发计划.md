# JSONSQLite v3.4.0 开发计划

> 包名：`@webofcat/jsonsqlite`（集群与 WASM 可拆包）  
> 主题：**集群实验**——选主、自动分片、跨机锁  
> 前置：单机生产 pin **LTS-2**，多写者 pin **LTS-3**，异步复制 pin **LTS-4** 均已存在。本版不替代它们  
> **LTS：否。本版禁止宣布 LTS，也禁止使用 Vision Complete 作为发版标题**  
> 兼容：集群 API 默认关闭。关闭时不得破坏 LTS-4 的单机与异步复制行为  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)

## 1. 为什么集群不能在这一版成为长期稳定版

方案把 Raft 放在单机与异步复制之后，并把 Phase 5 的验收写成复制 demo，而不是自动选主。选主、分片迁移和跨机锁只要有一条混沌断言不成立，就会静默丢写或双主。这种能力必须：

1. 先有独立 RFC（选主、分区、分片迁移中的读写）。  
2. 默认关闭交付。  
3. 至少再经过一个只修缺陷的版本，才**有资格另开 3.5 计划**讨论 LTS-5。3.5 不在本目录预写；没人能在 3.4 发版当天证明它已经浸泡过。

WASM 若做，只作为可选包，优先只读。写路径未经过与服务端相同的崩溃测试之前，标 experimental，不进入任何 LTS 承诺。

---

## 2. 目标

1. RFC 合并前不写实现。  
2. 三节点：能选出唯一主；杀死主后按 RFC 重新选出主；已提交数据仍在。  
3. 网络分区下不出现两个主同时接受写入。测试断言来自 RFC，而不是实现完再补文档。  
4. 自动分片 / rebalance：迁移过程中查询要么成功要么明确失败，不静默少文档。  
5. 跨机锁冲突有稳定错误码。  
6. 默认关闭。关闭时 FT-V32 的单机与复制回归绿。  
7. 任一混沌项失败：可以发布为 experimental 且默认关，但 Release 必须写失败项，**不能**把失败项写成已支持。

### 成功标准（实验发布，不是 LTS）

- RFC 链接在仓库中。  
- 混沌套件有结果：通过的项与未通过的项都写进 Release。  
- `lts: false`。  
- 文档告诉用户生产 pin 仍是 LTS-2，需要多写者用 LTS-3，需要异步复制用 LTS-4。

## 3. 需求

| ID | 需求 |
|----|------|
| V34-RFC-1 | 选主、分区、rebalance RFC |
| V34-CLU-1 | 选主与日志复制，默认关 |
| V34-CLU-2 | 自动分片与 rebalance |
| V34-CLU-3 | 跨机锁 |
| V34-CLU-4 | 混沌：杀主、杀从、分区 |
| V34-WASM-1 | 可选包；能力子集写清；可整版后移 |
| V34-CLI-1 | `cluster status\|join\|leave\|rebalance` 仅在功能开启时出现在稳定帮助中；未通过的子命令不得进冻结文档 |

---

## 4. 验收

- [ ] RFC 合并  
- [ ] 默认关闭时 LTS-4 回归绿  
- [ ] 混沌结果写入 Release，未通过的不称为支持  
- [ ] 发布说明含 **非 LTS**，且不含 Vision Complete  
- [ ] `getCompatibilityInfo().lts === false`  
- [ ] 不修改 `lts` / `lts-2` / `lts-3` / `lts-4` 的指向

---

## 5. 风险

| 风险 | 缓解 |
|------|------|
| 实验功能被装进主推荐 tag | 本版验收禁止改这些 tag |
| WASM 与集群绑死 | WASM 可单独延期，不作为集群发版条件 |
| 范围失控 | 分片策略先 hash-only；做不到就保持关闭并在 Release 写明 |
