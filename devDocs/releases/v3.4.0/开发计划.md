# JSONSQLite v3.4.0 开发计划

> 包名：`@webofcat/jsonsqlite`（集群与 WASM 可拆包）  
> 主题：**集群实验**——选主、自动分片、跨机锁  
> 前置：单机生产 pin **LTS-2**，多写者 pin **LTS-3**，异步复制 pin **LTS-4** 均已存在。本版不替代它们  
> **LTS：否。本版禁止宣布 LTS，也禁止使用 Vision Complete 作为发版标题**  
> 兼容：集群 API 默认关闭。关闭时不得破坏 LTS-4 的单机与异步复制行为  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)

## 1. 为什么集群不能在这一版成为长期稳定版

方案把 Raft 放在单机与异步复制之后，并把 Phase 5 的验收写成复制 demo，而不是自动选主。选主、分片迁移和跨机锁只要有一条混沌断言不成立，就会静默丢写或双主。这种能力必须：

1. 先有独立 RFC（选主、分区、分片迁移中的读写）。  
2. 默认关闭交付。  
3. 至少再经过一个只修缺陷的版本，才**有资格另开 3.5 计划**讨论 LTS-5。3.5 不在本目录预写；没人能在 3.4 发版当天证明它已经浸泡过。

WASM 若做，只作为可选包，优先只读。写路径未经过与服务端相同的崩溃测试之前，标 experimental，不进入任何 LTS 承诺。

## 2. 目标

1. RFC 合并前不写实现。  
2. 三节点：能选出唯一主；杀死主后按 RFC 重新选出主；已提交数据仍在。  
3. 网络分区下不出现两个主同时接受写入。测试断言来自 RFC，而不是实现完再补文档。  
4. 自动分片 / rebalance：迁移过程中查询要么成功要么明确失败，不静默少文档。  
5. 跨机锁冲突有稳定错误码。  
6. 默认关闭。关闭时 FT-V32 的单机与复制回归绿。  
7. 任一混沌项失败：可以发布为 experimental 且默认关，但 Release 必须写失败项，**不能**把失败项写成已支持。

### 成功标准（实验发布，不是 LTS）

- RFC 链接在仓库中。  
- 混沌套件有结果：通过的项与未通过的项都写进 Release。  
- `lts: false`。  
- 文档告诉用户生产 pin 仍是 LTS-2，需要多写者用 LTS-3，需要异步复制用 LTS-4。

## 4. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。集群实验最容易在 README 里被写成已经能当生产集群。只改版本号不算完成；把未通过的混沌项写成已支持，本版验收直接失败。

写作要求：

- 与 RFC、混沌套件结果、Release 用词一致。通过的项与未通过的项都写上。未通过的单独成段，标题用「未支持」，不用「即将」「基本可用」。
- 默认关闭。关闭时，单机与异步复制的既有说明仍然成立，并写明默认配置不启用集群。
- 文首写明 **3.4.0、非 LTS**，不得出现 Vision Complete。`lts: false`。生产 pin 仍是：单机 **LTS-2**，多写者 **LTS-3**，异步复制 **LTS-4**。本版不替代它们。
- 不修改 `lts` / `lts-2` / `lts-3` / `lts-4` 的指向。README 的安装说明与这些 tag 一致，不引导读者把 3.4 装成 `latest` 之外的推荐线；若 `latest` 指向本版，必须在同一段写明这不是生产 pin。

本版 README 必须写清：

1. 默认关闭的打开方式，以及不打开时行为与 LTS-4 的单机、异步复制相同。把「如何保持关闭」放在「如何打开集群」之前。
2. 链接已合并的 RFC（选主、分区、分片迁移中的读写）。步骤与断言来自 RFC，不在 README 里另起一套高可用叙述。
3. 选主：仅当对应混沌项通过时，写三节点如何选出唯一主、杀死主后如何按 RFC 重新选出、已提交数据仍在。给出状态命令与「唯一主」在输出里的字段。未通过则放进「未支持」，不提供成功示例。
4. 网络分区：仅当通过时，写明不出现两个主同时接受写入，以及测试所依据的断言（错误码或拒绝结果）。不要用「高可用」「自动容灾」代替断言。
5. 自动分片 / rebalance：仅当通过时，写明迁移过程中查询要么成功要么明确失败，不静默少文档。失败时的稳定错误码和调用方如何重试或停写。做不到则保持关闭，并写「本版未启用自动分片」，不要写计划中的策略细节冒充行为。
6. 跨机锁：仅当通过时，写冲突的稳定错误码和锁的范围（哪些操作会碰到）。未实现则不要出现在 API 示例里。
7. CLI：`cluster status`、`join`、`leave`、`rebalance` 只有在功能开启且该子命令已通过时，才写入稳定用法，并附示例。未通过的子命令不得出现在命令一览或「快速开始」里。
8. WASM：若随本版以可选包发布，写明包名、只读优先、experimental、不进入任何 LTS 承诺。写路径未经过与服务端相同的崩溃测试之前，不得写成可写。若本版不包含 WASM，只写「本版未包含」，不写发布日期。
9. 写明 **3.5 / LTS-5 尚未存在**。至少再经过一个只修缺陷的版本，才有资格另开计划讨论下一条 LTS。本 README 不承诺下一版成为长期稳定版。

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 实验功能被装进主推荐 tag | 本版验收禁止改这些 tag |
| WASM 与集群绑死 | WASM 可单独延期，不作为集群发版条件 |
| 范围失控 | 分片策略先 hash-only；做不到就保持关闭并在 Release 写明 |
