## 1. 为什么这个版本不能当 LTS

长期稳定版只打在「行为已经浸泡、发版本身不再引入新子系统」的版本上。2.0 要改恢复、隔离和存储布局，属于浸泡期。通过本版与 2.1 的运维闭环之后，**2.2** 才冻结为生产 pin。

本版同时明确：**多写者、复制、Raft、列存格式、插件、GraphQL 都不进 2.0。** 方案 §13 将多进程写标为损坏风险；这些红线未绿之前扩大并发面，不能称为生产级。

## 2. 目标

1. **备份链可恢复**：全量与增量都能按顺序恢复；checksum 不符拒绝恢复，且不写入目标库。支持按集合的部分恢复。  
2. **WAL 失败关闭**：日志尾部不完整的一行可以丢弃；中间行校验失败则 `open` 失败，错误码稳定，禁止跳过已提交记录。  
3. **隔离级别诚实**：`READ_COMMITTED` 保持默认。`REPEATABLE_READ` 在 `begin` 建立快照，事务内重复读不看见之后提交的写入。允许并发只读快照，写事务仍全局一个。`SERIALIZABLE` 与 `READ_UNCOMMITTED` 返回明确的未实现错误，禁止静默降级。  
4. **外存分页**：点查与过滤不把整表载入堆。可配置内存页上限。百万文档场景的测试要证明工作集受页预算约束。  
5. **提交后索引与数据一致**；损坏的索引分段拒绝使用，`doctor` 报出原因。  
6. **Admin**：非 loopback 必须同时具备 token 与 TLS 材料，缺一拒绝监听。loopback 保持 token 可选，并打印警告。  
7. **容量包络**：按方案 §12.3 六个场景写出本机实测数字，写入发版说明。CI 继续守相对回归，不把大纲里的绝对毫秒数当作验收。  
8. **迁移**：`1.8 → 2.0`，含明文库与加密库；损坏源拒绝且不留半成品。

### 成功标准

- 上列 1–4 有自动化测试，且失败时非 0 退出、库不被半写入。  
- 分页测试：打开超过页预算的集合时，堆上的驻留文档数有上限断言。  
- `getCompatibilityInfo()` 标明 `2.0.0`、`lts: false`、单写者。  
- FT-V20-* 全绿。

### 不做

| 项 | 留给 |
|----|------|
| 多写者、死锁、SERIALIZABLE | **2.4**（浸泡）→ **2.5 LTS-3** |
| 差异备份、保留策略、定时备份、告警、审计、自动修复 | **2.1** |
| 列存、热/温/冷正式布局、智能压缩、插件、Geo | **2.3**（默认关，须能开 2.2 库） |
| 复制、Quorum、读写分离 | **3.0–3.1**，**3.2 = LTS-4** |
| Raft、自动分片、WASM | **3.4** 实验，**首发禁止宣布 LTS** |
| GraphQL、连接池、多库、框架包 | **3.3** |
| 完整 SQL、替代 ES/ClickHouse、强制 LLM | **⛔** |

## 3. 需求摘要

| ID | 需求 | 目标行为 |
|----|------|----------|
| V20-MIG-1 | 迁移 | `migrate` 与库 API；校验源库 checksum；失败不留目标目录 |
| V20-BK-1 | 增量恢复 | full 之后按序应用 incremental；缺基线则失败 |
| V20-BK-2 | 恢复校验 | manifest checksum 不符则拒绝，目标库不变 |
| V20-BK-3 | 部分恢复 | 指定集合从全量备份恢复，其它集合不动 |
| V20-WAL-1 | 失败关闭 | 非尾部坏行 → `CORRUPT_WAL`（或等价稳定码） |
| V20-ISO-1 | RR 快照 | 只读快照与一个写事务可并存；快照不看 begin 之后的提交 |
| V20-ISO-2 | 未实现级别 | SER / READ_UNCOMMITTED 抛错，配置校验同样拒绝 |
| V20-PAGE-1 | 分页存储 | 页缓存有上限；点查加载所在页；reopen 不整表 rebuild 进堆 |
| V20-IDX-1 | 索引诚实 | 坏分段不服务查询；doctor 列出分段与原因 |
| V20-TLS-1 | Admin TLS | 非 loopback：token + TLS，否则 `INVALID_CONFIG` |
| V20-PERF-1 | 包络 | §12.3 六场景写入 `apps/bench` 报告与 Release |
| V20-DOC-1 | 契约 | API.md 写明单写者、RC+RR、分页、备份链；列出相对 1.8 的破坏点 |
| V20-CLI-1 | CLI | 见下表 |

### CLI（2.0）

| ID | 命令 | 说明 |
|----|------|------|
| V20-CLI-A | `migrate --from --to --yes` | 1.8→2.0 主入口 |
| V20-CLI-B | `backup restore --type full\|incremental` | 与库 API 同一条恢复路径 |
| V20-CLI-C | `backup restore --collection <name>` | 部分恢复 |
| V20-CLI-D | `doctor` | 区分尾部撕裂与中间损坏 |
| V20-CLI-E | `CLI-API.md` 2.0 | 破坏清单；**不**加入 plugin / replica / cluster |

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 分页与 1.8 索引分段格式冲突 | formatVersion 升级只走 migrate |
| RR 在单写者上测不出差异 | 测试使用只读快照与另一次已提交写入的交错，而不是第二个写者 |
| 范围膨胀回潮到复制/列存 | 本表「不做」是发版门禁，不是备注 |
