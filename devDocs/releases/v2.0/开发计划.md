# JSONSQLite v2.0.0 开发计划

> 包名：`@webofcat/jsonsqlite`（若拆包则同步修订《npm包与后端接入说明》）  
> 主题：**下一代引擎（设计 P5 核心）——允许破坏兼容**  
> **LTS 标注：否**（破坏性首发浸泡期；**勿**当作长期 pin；硬化见 2.1 → **LTS-2 = 2.2**）  
> 前置：建议 **1.8** 完成索引落盘与性能基线；**LTS-1（1.6）** 仍可维护安全补丁  
> 兼容：**MAJOR**——允许破坏 API / 默认值 / 存储布局；必须提供迁移指南  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 完工矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)

## 1. 背景与目标

设计文档与 vs SQLite 差异化中，**多写者、列存、插件、异步复制** 被明确排除在 v1 / 1.6 LTS 之外。1.6–1.8 把单写者嵌入式做到可 pin 后，2.0 的使命是：

1. **正确性前提下** 引入可控的多写者或「单主多读」模型（优先单机多进程，而非一上来 Raft）  
2. 落地 **列存 / 分层存储**（大纲 AdaptiveStorage 的生产裁剪版）  
3. 提供 **插件面**：自定义索引（含 vector 占位）、冷存储（如 S3 示例）  
4. 交付 **异步复制雏形**（弱一致、可配置），并诚实文档化局限  
5. 重新审视 **Schema 默认**：可改为 `warn` 或提供 `strict` 预设 profile，破坏须写升级指南  

```text
1.6 LTS ──维护──► 1.6.x
1.7 / 1.8 ──功能线──►（可止于 1.8）
                ╲
                 ╲──► 2.0 破坏性一代   ← 本文
```

### 2.0 成功标准

1. 公开 **迁移指南**：1.8（或 1.6）→ 2.0；含 `formatVersion` 升级与不兼容项清单  
2. 多写者 **或** 明确的单主多读 API：有锁协议、冲突错误码、集成测试；禁止静默损坏  
3. 列存或混合存储：至少一种分析型查询可测加速（对比文档模式）  
4. 插件注册 API 稳定；示例：自定义索引 + 冷存储 stub  
5. 异步复制 demo：≥2 节点最终可见写入；故障手册说明脑裂策略（不做强一致承诺）  
6. FT-V20-* 全绿；旧版数据经官方工具可迁  

### 2.0 不做（再往后）

| 项 | 留给 |
|----|------|
| RR/SER 隔离、死锁、差异备份、告警审计 | **2.1** |
| Geo / L3 Redis / 读写分离 / LTS-2 冻结 | **2.2 LTS-2** |
| GraphQL / 连接池 / 多库 | **2.3** |
| Raft 选主、自动分片、WASM、Vision Complete | **3.0 LTS-3** |
| 完整替代 ClickHouse / ES / 完整 SQL 方言 | **⛔ 产品边界**（见 MATRIX） |

## 4. 破坏性变更预告（草案，RFC 可改）

| 类别 | 可能变更 |
|------|----------|
| API | 锁/事务语义；弃用符号删除（如已 deprecated 的 `dropCollection`） |
| 默认值 | `schemaMode` / `lazyCollections` / 缓存大小 |
| 磁盘 | 列存目录布局；索引分段格式；加密包络版本 |
| CLI | 子命令重组或迁移命令取代部分旧运维路径 |

1.6 用户路径：继续 pin `1.6.x` → 读迁移指南 → 测 → 升 2.0。

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 多写者正确性陷阱 | 先单主多读；多写者需长时间 soak |
| 范围膨胀拖死发版 | 分片/Geo 可标 experimental |
| 1.6 用户被迫升级 | 明确 1.6 维护窗口；迁移工具优先 |
| 性能宣传翻车 | 只对比自身文档模式 / 声明场景 |
