# JSONSQLite v2.0.0 功能测试计划

> 用例前缀：`FT-V20-*`  
> 重点：迁移、并发模型、列存/分层、插件、异步复制  
> 破坏性版本：兼容性测试以「迁移后正确」为准，不以「旧二进制直开」为硬性要求

---

## 0. 门禁

| ID | 场景 | 期望 |
|----|------|------|
| FT-V20-GATE-01 | RFC 已合并 | 并发模型与格式版本写清 |
| FT-V20-GATE-02 | 迁移工具存在 | 1.8（或约定源版本）样例库可迁 |

---

## 1. 迁移

| ID | 场景 | 期望 |
|----|------|------|
| FT-V20-MIG-01 | 明文库迁移 | 文档数/抽样内容一致 |
| FT-V20-MIG-02 | 加密库迁移 | 需正确密钥；错误密钥失败干净 |
| FT-V20-MIG-03 | 损坏源拒绝 | 非 0；不写半成品目标 |
| FT-V20-MIG-04 | 幂等/重跑 | 文档化行为（覆盖或拒绝）可测 |

## 2. 并发

| ID | 场景 | 期望 |
|----|------|------|
| FT-V20-CON-01 | 双写者压力 | 无静默丢写；冲突有明确 code |
| FT-V20-CON-02 | 读多写一（若模型支持） | 读不阻塞合理；数据最终一致 |
| FT-V20-CON-03 | 崩溃注入 | 恢复后已提交在、未提交不在 |
| FT-V20-CON-04 | 与旧「第二 open 即 LOCK_FAILED」对比 | 行为符合 RFC（可能改变） |

## 3. 存储

| ID | 场景 | 期望 |
|----|------|------|
| FT-V20-STOR-01 | 列存/混合投影 | 结果正确；有加速证据或可解释的计划信息 |
| FT-V20-STOR-02 | 分层冷读 | 冷文档可读 |
| FT-V20-STOR-03 | vacuum / doctor | 适配新布局；unhealthy 可检出 |

## 4. 插件 / 复制

| ID | 场景 | 期望 |
|----|------|------|
| FT-V20-PLG-01 | 注册自定义索引 | 查询可走插件 |
| FT-V20-PLG-02 | 冷存储 stub | 读写钩子被调用 |
| FT-V20-REP-01 | 主从异步 | 从节点最终可见主写入 |
| FT-V20-REP-02 | 从节点落后可观测 | metrics/doctor 有滞后信号 |
| FT-V20-REP-03 | 主宕机 | 文档化行为；测试断言符合 RFC（不假装自动选主除非实现了） |

## 5. 文档 / 发布

| ID | 场景 | 期望 |
|----|------|------|
| FT-V20-CLI-01 | `migrate --help` / 干跑或成功路径 | 非 TTY；`--json` 包络稳定 |
| FT-V20-CLI-02 | `plugin list` | exit 0；JSON 可选 |
| FT-V20-CLI-03 | `replica status`（若交付） | 可脚本化 |
| FT-V20-DOC-01 | API.md / CLI-API 覆盖破坏点与新 API / 新命令 | 导出 ⊆ 文档；help ⊆ CLI-API |
| FT-V20-DOC-02 | 升级指南可跟做 | 人工 checklist 通过 |
| FT-V20-VER-01 | `getVersion()` / 兼容信息 | `2.0.0`；标明 major |

---

## 验收（2.0 放行）

1. GATE + MIG + CON 必选全绿  
2. 列存与复制至少达到「demo + 自动化冒烟」  
3. Release notes 完整列出破坏项与迁移命令  
4. 宣布与 1.6 LTS 的关系（并行维护窗口或 EOL 日期）
