# JSONSQLite v1.6.0 开发计划（长期稳定版 / LTS）

> 包名：`@webofcat/jsonsqlite`  
> 主题：**长期稳定（LTS）官宣 + 公开契约冻结 + 完整用户文档**  
> 前置假设（硬门禁）：  
> - `1.5.0`：引擎/运维生产就绪（rekey、lazy、vacuum、deep doctor、压测）  
> - **`1.5.5`：CLI 命令面、交互、脚本契约已达可冻结质量**，并产出命令 inventory  
> 定位：在 **单写者、嵌入式、软 Schema 默认** 约束下，推荐生产 pin 的 1.x 终点版本

---

## 0. 与 1.5.5 的关系（必读）

插队的 **1.5.5** 改变了 1.6 的工作重心：

| 维度 | 1.5.5 负责 | 1.6.0 负责 |
|------|------------|------------|
| CLI 新命令 / UX / flags / exit code | **实现并定稿** | **冻结并写入** 根目录 `CLI-API.md`，禁止大改 |
| CLI help 分级、`--json` 形状、TTY 门禁 | 定稿 | 契约测试锁定；仅允许勘误级修正 |
| 命令 inventory | 产出底稿 | 升格为 `CLI-API.md` 真源 |
| 后端库 API 手册 | 不强制 | **`API.md` 强制** |
| LTS 官宣与支持年限 | 不宣称 | **唯一官宣节点** |

**因此 1.6.0 不再规划「补齐 CLI 常用命令」**——若 1.5.5 验收未过，不得进入 1.6 文档冻结与发版。

1.6 允许的 CLI 改动仅限：

1. 文档与实现不一致时的 **小修正**（优先改文档；改行为须进 CHANGELOG 且向后兼容）  
2. help 文案勘误、示例补全  
3. 安全相关紧急修复  

**禁止**在 1.6 重新设计交互流、新增一大批子命令（应回到 1.5.x 或等到 1.7/2.0）。

## 1. 背景与目标

```text
1.3  硬化基线
1.4  安全与查询能力
1.5  生产就绪（rekey / 性能 / 运维 / 压测）
1.5.5 CLI LTS 化（常用命令 + 交互/脚本契约）← CLI 冻结面来源
1.6  LTS：冻结契约 + 根目录权威文档 + 支持策略   ← 本文
2.0  下一代（允许破坏兼容）
```

**1.6.0 的核心不是堆新功能**，而是：

1. 把 1.3–**1.5.5** 的能力收成 **可承诺的长期契约**（库 API + **已定稿的 CLI 面**）  
2. 在**仓库根目录**交付两份权威文档（见 §3，强制）  
3. 清掉文档 / 实现 / CLI help / **1.5.5 inventory** 四者不一致  
4. 定义 **1.6.x 支持策略**  
5. 用完整回归（含 **FT-V155**）+ 兼容性矩阵证明「可 pin」  

允许的少量功能仅限于：**不破坏契约的缺陷修复、文档化缺口补齐、LTS 必需的诊断/元信息 API**（例如 `getCompatibilityInfo()`）。

### 1.6 成功标准（LTS 门禁）

1. **前置**：`1.5.5` 已发布；`devDocs/releases/v1.5.5` 命令 inventory（或等价产物）存在且与 help 一致  
2. 根目录存在并审阅通过：  
   - **`CLI-API.md`**：覆盖 **1.5.5 全命令面**（含 insert/update/delete/get/count/index/stats/explain/sql REPL 等）  
   - **`API.md`**：后端可 `import` 的全部稳定 API  
3. `exports` / 类型导出与 `API.md` 一一对应  
4. CLI 契约测试：help ⊆ `CLI-API.md`；exit code / `--json` / `--yes` / TTY 规则与 1.5.5 定稿一致  
5. SemVer / LTS 政策写入 README + 两份根文档文首  
6. FT-V16-* 全绿；回归含 **V12–V15 + V155**  
7. 发布 `@webofcat/jsonsqlite@1.6.0`，Release 注明 **LTS**  
8. 明确非目标：多写者等属 2.0；**不再在 1.6 扩 CLI 功能面**

## 3. 强制文档交付（仓库根目录）

> **硬性要求**：1.6.0 合并与发版前，必须在仓库**根目录**生成并维护以下两份文档。  
> 路径固定（勿只放在 `devDocs/`）：

| 根目录文件 | 受众 | 内容定位 |
|------------|------|----------|
| **`CLI-API.md`** | CLI 用户与运维 | **以 1.5.5 定稿命令面为准**的完整手册 |
| **`API.md`** | Node 后端 | 全部稳定 `import` API |

`devDocs/releases/v1.5.5/cli-command-inventory.md`（或 1.5.5 约定的等价产物）是 `CLI-API.md` 的**输入底稿**，不能替代根目录终稿。

### 3.1 `CLI-API.md` 必须包含的章节

> 下列命令集合以 **1.5.5 开发计划 §2** 为准；若 1.5.5 实现有微调，以 inventory + help 快照为准更新本节，而不是在 1.6 另起炉灶。

1. 安装与版本：`npm i -g`、`--version`、`jsql` 别名  
2. **全局契约（1.5.5 定稿）**  
   - flags：`-p/--path`、`-y/--yes`、`--json`、`-q/--quiet`、`-h/--help`  
   - exit code：`0` 成功 / `1` 业务参数 / `2` 系统 IO / `3` 锁失败（若 1.5.5 最终定稿有出入，以定稿为准并在此写死）  
   - TTY vs 非交互；`NO_COLOR`  
   - `--json` 成功/失败包络形状  
3. 数据库生命周期：`create` / `init`  
4. 表命令：`tables`、`table create|drop|alter|show|describe|export|import`  
5. **行级常用命令（1.5.5 新增）**：`insert` / `update` / `delete` / `get` / `count`  
6. **索引与诊断**：`index list|create|drop`、`stats`、`explain`  
7. SQL：`run`、**`sql` REPL**（仅 TTY；非 TTY 行为）  
8. 运维：`doctor` / `doctor --deep` / `backup` / `vacuum` / `rekey`、`query`  
9. 环境变量与安全（密钥、路径权限）  
10. **完整命令速查表**（契约测试输入；须与 1.5.5 inventory 对齐）  
11. 变更策略：1.6.x **不得无说明删除** 1.5.5 已发布的稳定子命令；新增子命令不属于 1.6.x 范围  

### 3.2 `API.md` 必须包含的章节

1. 安装与双格式（ESM / CJS）  
2. 快速开始  
3. **生命周期**：`create` / `init` / `open` / `close` / `getVersion` / `getCompatibilityInfo`（若有）  
4. **配置**：`JSONSQLiteOptions` 全字段（含 1.4/1.5：`syncMode`、`schemaMode`、`encryptionKey`、`lazyCollections` 等）  
5. **表 / 集合 DDL**  
6. **文档 CRUD**  
7. **查询**：`query`、`count`、`queryCursor`、`aggregate`、`jsonPath`  
8. **SQL**：`run`、`parseSql`；支持与不支持清单  
9. **索引 / 事务**（隔离级别真实语义）  
10. **备份 / 时间旅行 / 监控 / 质量 / Advisor**  
11. **导出导入 / vacuum / rekey**  
12. **HTTP Admin**  
13. **事件** `subscribe`  
14. **ErrorCode** 全表  
15. **类型导出表**  
16. **LTS 兼容承诺与已知限制**（含：CLI 细节以 `CLI-API.md` 为准）  
17. 升级指南：**1.5.5 → 1.6.0**（通常无破坏；核对 CLI 脚本是否依赖旧 help 文案）

## 5. LTS 兼容承诺（写入文档的条文草案）

在 1.6.x 生命周期内，**保证**：

1. 不删除、不重命名 `API.md` 中的稳定符号（除非 major）  
2. 不缩小已承诺 SQL 语义（安全修复除外并记 CHANGELOG）  
3. `formatVersion` 升级必须可迁移，否则升 major  
4. **不删除、不默默重命名 1.5.5 已发布的稳定 CLI 子命令**；全局 flags（`--json` / `--yes` / `-p` 等）语义保持兼容  
5. exit code 与 `--json` 错误包络保持兼容（可新增字段，不可删已文档化字段）  

**不保证**：

1. 多进程多写  
2. 性能绝对值  
3. `@internal` / 测试钩子  
4. Admin HTML 视觉细节  
5. **在 1.6.x 新增** 与 1.5.5 同等级的 CLI 功能面扩张
