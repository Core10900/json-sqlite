# JSONSQLite v1.4.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**安全增强 + 查询增强**（在 1.3 硬化基线上补齐「可安心用」与「更好查」）  
> 前置：1.3.0 已具备耐久写、DDL journal、软 Schema、`run` SQL 子集

---

## 1. 背景与目标

1.3.0 已把 Critical 耐久性/诚实 API 缺口补上，但仍明确留给后续：

- 主存储加密（当前仅备份可加密）
- 更完整的 SQL（LIKE 通配、简单 JOIN）
- 规模与运维体验（大表、导出导入、Admin 鉴权默认更安全）

**1.4.0 不做**：多写者、Raft/复制、列存、默认硬 Schema 破坏兼容——这些归 **2.0**。

### 1.4 成功标准

1. 可选 **主存储 AES 加密**（集合 JSONL + WAL），密钥来自配置 / `JSONSQLITE_KEY`
2. SQL **`LIKE` 支持 `%` / `_`**；支持 **两表等值 JOIN**（`INNER` / `LEFT`）
3. 库 API：`exportCollection` / `importCollection`；游标式分页 `queryCursor`
4. CLI：`table export|import`；`run` 覆盖新 SQL
5. Admin：未设 token 时限制为 loopback，并明确告警；补充加密备份往返测试
6. 文档与 FT-V14-* 全部通过；发版 `1.4.0`

## 4. 技术方案要点

### 4.1 主存储加密

- 算法：与备份一致的 **AES-256-GCM**
- 粒度：按 **行（JSONL 一行）** 或按 **文件块**；建议行级密文 Envelope，便于 WAL 追加
- 明文探测：文件头 magic / catalog 标记 `encryption: true`，避免误用密钥
- **兼容**：无密钥的旧库保持明文；开启加密为 **新库或显式迁移**（1.4 可用 export→create 加密库→import）

### 4.2 LIKE

| 模式 | 语义 |
|------|------|
| `%` | 任意长度 |
| `_` | 单字符 |
| `\%` `\_` | 字面量（若实现转义） |

不实现 `ESCAPE` 子句可列为 1.4.1；默认 `\` 转义或文档声明「无转义」。

### 4.3 JOIN（v1）

```sql
SELECT u.name, o.total
FROM users u
INNER JOIN orders o ON u._id = o.userId
WHERE o.total > 100
ORDER BY o.total DESC
LIMIT 20
```

- 仅 **一张驱动表 + 一张被连接表**
- `ON` 仅 **等值**（`a.col = b.col`）
- 投影支持 `table.col` / 别名；`*` 展开为两侧字段（冲突加前缀）

### 4.4 游标分页

```ts
const page1 = await db.queryCursor({
  collection: 'users',
  orderBy: { age: 'asc', _id: 'asc' },
  limit: 50,
});
const page2 = await db.queryCursor({
  collection: 'users',
  orderBy: { age: 'asc', _id: 'asc' },
  cursor: page1.nextCursor,
  limit: 50,
});
```

## 5. 非目标（明确不做）

| 项 | 原因 |
|----|------|
| 多进程多写 / 分布式锁 | 2.0 |
| 三表及以上 JOIN、子查询、窗口函数 | 复杂度；后续 minor/major |
| 默认 `schemaMode: 'strict'` | 破坏现有 1.x 用户；保持 opt-in |
| 在线改密钥 rekey | 可放到 1.4.x 或 1.5 |
| 磁盘列存 / 外部分页存储 | 2.0 存储引擎议题 |
| 完整 SQL 事务（`BEGIN`） | 已有 API 事务；SQL 事务语法后置 |
