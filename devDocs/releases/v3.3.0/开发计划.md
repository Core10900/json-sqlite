# JSONSQLite v3.3.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**异步复制雏形**  
> 前置：**3.2.0** 的 PITR 与单机回归已绿。复制建立在已经能按时间恢复的单机之上  
> **LTS：否**。本版也不是设计完工版  
> 兼容：相对 3.2 为 **MAJOR**（复制日志格式）。不开启复制时必须仍能打开 3.2 / 2.5 库，行为与 LTS-3 默认单写者一致  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)  
> npm 标签与发布后核对：[发布说明.md](./发布说明.md)

---

## 1. 目标

1. 复制默认关闭。关闭时回归 3.2 的单机测试。  
2. 开启后：一个主、一个或多个从。主的已提交写入最终在从库可见。提交成功只表示主库本地提交，不表示从库已经收到。  
3. 从库滞后可在 metrics、`doctor` 和 `replica status` 中读到。字段单位在 README 里写死。  
4. 主宕机：**不**自动选主。从库停在已复制的前缀，不接受写入冒充新主。提升从库是显式命令。没有这条命令时，从库保持只读前缀。  
5. hash/range 分片路由可以有实验开关，默认关。开关关闭时单机路径不经过路由器。实验失败不阻塞本版其余功能；未实现则不要出现在稳定 CLI 里。  
6. 提供 3.2 → 3.3 的单机迁移。开启复制不是迁移的必选项。2.5 库在复制关闭时也能直接打开。  
7. 复制关闭时 `/health` 不因为没有从库而失败。复制打开后，`/health` 含角色和滞后，单位与 `replica status` 相同。  
8. `replica` 配置写入 `config.example.json` 且默认关闭，`config validate` 不再把它当危险键。`cluster`、`graphql`、`wasm` 仍拒绝。

### 成功标准

- 两节点最终可见有自动化测试。  
- 杀死主进程后，从库不接受写入，除非用户执行文档中的提升命令。  
- 稳定帮助里没有 `cluster`，没有 failover。  
- FT-V33-* 全绿。Release 标题含 **非 LTS**，不含设计完工或 Vision Complete。

### 不做

Quorum 写成功条件、读写分离、可用 S3、Raft、自动 rebalance、跨机锁、GraphQL、连接池、多库、WASM。Quorum 与接入层在 **3.4**。选主在 **3.5**。冻结在 **3.6**。

## 3. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。只改版本号、或把主从写成已经高可用，都不算完成。

写作要求：

- 说明文字用中文。本版改到的 `packages/core/README.md` 与仓库根 `README.md` 都用中文写。命令、配置键、错误码和代码示例保持原文。用英文段落代替中文说明不算完成。
- 与复制 RFC、默认关闭、以及「不自动选主」的测试断言一致。提升从库只写成显式命令。
- 读者要能判断：不开启复制时库是否仍是单机、如何打开复制、滞后看哪里、主宕机后自己要做什么。
- 示例使用真实配置、API 与 `replica` 命令，可复制。未进入稳定 CLI 的能力不出现在命令一览里。
- 文首写明 **3.3.0、非 LTS**。单机生产 pin 在 3.6 宣布前仍是 LTS-2 / LTS-3。

本版 README 必须写清：

1. 兼容：相对 3.2 为 MAJOR（复制日志格式）。不开启复制时打开 2.5 / 3.2 库，行为与 LTS-3 默认单写者一致。用对照写「关闭」和「开启」两种启动方式。
2. 拓扑是一个主、一个或多个从。写明「最终可见」不是同步确认。主库提交成功不能当成从库已经收到。
3. `replica init` 与 `replica status` 的示例。滞后在 metrics、`doctor`、`replica status` 中的字段名和单位。滞后变大时读者第一步看什么。
4. 主宕机后的步骤：从库保持只读前缀；`replica promote` 的命令顺序、危险点、执行前数据停在哪里。没有这条命令时从库拒绝写入，写明错误码。
5. 分片：若本版实现了默认关闭的 hash/range 开关，写明默认关、失败不影响单机、不在未打开时出现于稳定帮助。若未实现，README 不出现「已支持分片」。
6. 迁移 **3.2 → 3.3** 与 **2.5 → 3.3** 的单机步骤。开启复制单独标成可选项。
7. 路线：Quorum、读写分离、可用冷存储和接入层在 **3.4**。选主在 **3.5**。长期稳定线是 **3.6**。本版不做 Raft、自动 rebalance、跨机锁、GraphQL、WASM。
8. CLI 有 `replica init`、`replica status`、`replica promote`，没有 `cluster`。  
9. `/health` 在两种开关下的字段。复制关闭时状态不是失败。  
10. `config.example.json` 里的复制段默认关闭。`config validate` 接受它，仍拒绝 `cluster`。
