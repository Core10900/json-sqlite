# JSONSQLite v3.3.0 功能测试计划

> 前缀：`FT-V33-*`  
> **非 LTS**。不是设计完工放行。不要求 Quorum 或集群。

## 0. 门禁

| ID | 场景 | 期望 |
|----|------|------|
| FT-V33-GATE-01 | 复制 RFC | 含「不自动选主」与 `replica promote` 步骤 |
| FT-V33-REG-01 | 复制关闭 | 3.2 单机回归绿，仍是默认单写者 |
| FT-V33-VER-01 | version | `3.3.0`，`lts: false` |

## 1. 复制

| ID | 场景 | 期望 |
|----|------|------|
| FT-V33-REP-01 | 主写入 | 从库在文档化的延迟内可见 |
| FT-V33-REP-02 | 主已提交、从尚未应用 | status 不把该写入标成已复制 |
| FT-V33-REP-03 | 从库落后 | metrics、`doctor`、`replica status` 使用同一滞后单位 |
| FT-V33-REP-04 | 杀死主进程 | 从库拒绝写入；已复制前缀仍在 |
| FT-V33-REP-05 | `replica promote` | 只有命令成功之后，原从库才可写 |
| FT-V33-MIG-01 | 2.5 与 3.2 库迁移且不启复制 | 抽样一致；仍是单写者 |
| FT-V33-HLT-01 | 复制关闭的 `/health` | 成功，且不报告复制失败 |
| FT-V33-HLT-02 | 复制打开的 `/health` | 角色和滞后与 `replica status` 一致 |
| FT-V33-CFG-01 | `config validate` | 接受默认关闭的 `replica`；拒绝 `cluster` |

## 2. CLI 与文档

| ID | 场景 | 期望 |
|----|------|------|
| FT-V33-CLI-01 | `replica status --json` | 非 TTY，含角色与滞后 |
| FT-V33-CLI-02 | 稳定帮助 | 无 `cluster`，无 failover |
| FT-V33-SHD-01 | 默认配置 | 请求不经过分片路由器 |
| FT-V33-DOC-01 | Release | 含非 LTS，不含设计完工或 Vision Complete |

## 放行

1. REG、REP-01 至 REP-05 全绿。  
2. 出现自动选主，或帮助里出现 `cluster`，不得发版。
