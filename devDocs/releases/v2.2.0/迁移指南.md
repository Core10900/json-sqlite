# 1.6 / 1.8 → 2.2 迁移指南

> 包：`@webofcat/jsonsqlite@2.2.0`（**LTS-2**）  
> 1.6 与 1.8 都是磁盘 `formatVersion: 1`。2.2 不能直接 `open` 它们。  
> 迁移之后默认仍是**单写者**。本指南不打开多写者、复制或集群。

## 样例文档

下面的行是 1.8（以及同样布局的 1.6）库里 `collections/users/docs/data.jsonl` 的一行。迁完后 `_id` 仍是 `u1`，`name` 仍是 `寒`。

```json
{
  "_id": "u1",
  "_version": 1,
  "_createdAt": 1,
  "_updatedAt": 1,
  "name": "寒"
}
```

对应的 `meta/catalog.json`：

```json
{
  "formatVersion": 1,
  "collections": {
    "users": { "name": "users", "createdAt": 1, "documentCount": 1 }
  }
}
```

## 步骤

1. 停掉持有该目录的进程。把目录复制出来：`cp -R ./data ./data-1x-backup`。
2. **仅当 1.8 开过 `tiering: true`。** `cold.jsonl` 里的文档不会被 `migrate` 读到。在换成 2.2 之前，用 **1.8** 的二进制执行 `open({ storagePath, tiering: false })` 然后 `close()`，让冷文档回到 `data.jsonl`。1.6 没有这层文件，跳过这一步。2.2 的 `open` 对 format 1 会抛 `MIGRATION_REQUIRED`，不能用来做这一步。
3. 安装 2.2.0：`npm install @webofcat/jsonsqlite@2.2.0`。不要对旧目录调用 `open`。
4. 迁到新目录。明文：

   ```bash
   jsonsqlite migrate --from ./data --to ./data-v2 --yes
   ```

   加密库加上 `--from-key`（或环境变量 `JSONSQLITE_KEY`）。密钥不对时不会留下目标目录。

   ```bash
   jsonsqlite migrate --from ./data --to ./data-v2 --yes --from-key "$JSONSQLITE_KEY"
   ```

   `--from` 与 `--to` 必须是不同目录。目标已存在时，没有 `--yes` 会拒绝并且不改目标。

5. 打开 `./data-v2`。抽样：`findById('users', 'u1')` 的 `name` 是 `寒`。`formatVersion` 是 2。默认隔离级别是 `READ_COMMITTED`。第二个进程再 `open` 同一目录得到 `LOCK_FAILED`（CLI 退出码 3）。
6. 换密钥是另一步，不是 migrate 的一部分：

   ```bash
   jsonsqlite rekey --out ./data-v3 --to-key NEW --from-key OLD -p ./data-v2
   ```

## CLI 差异

1.6 已有的子命令**不改名**（`insert`、`update`、`delete`、`get`、`count`、`run`、`sql`、`doctor`、`vacuum`、`rekey` 等）。

1.6 之后加上、并在 2.2 冻结的命令：

| 命令 | 来自 |
|------|------|
| `compat` / `version --json` | 1.7；2.2 起含 `lts: true` 与 `ltsLine: "2.2"` |
| `admin serve`、`advise`、`aggregate`、`watch` | 1.7 |
| `index rebuild`、`vacuum --compress` | 1.8 |
| `migrate --from --to --yes` | 2.0 |
| `backup --type full\|incremental\|differential`、`backup prune`、`backup restore` | 2.0 / 2.1 |
| `tune`、`audit list` | 2.1 |
| `config validate --file` | 2.2 |

没有 `plugin`、`replica`、`cluster`。全局 flag 仍是 `-p/--path`、`-y/--yes`、`--json`、`-q/--quiet`。退出码仍是 `0/1/2/3`。

## 2.2.x 补丁

`2.2.x` 不新增命令、不改默认值、不升 `formatVersion`。若安全修复必须动格式，该补丁会自带迁移，并写进本指南。2.2.0 没有这种迁移。
