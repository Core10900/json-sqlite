## 1. 为什么 2.2 可以当 LTS

同时满足四条才宣布长期稳定：

1. 新子系统已经在 2.0 和 2.1 落地，本版只冻结，不再引入分页、隔离、备份或告警的新行为。  
2. 方案 §12.2 在单写者契约下全绿：已提交可恢复、版本单调、提交后索引一致、备份校验失败则拒绝。  
3. 宣布之后，`2.2.x` PATCH 不新增命令、不改默认值、不升 `formatVersion`（安全修复若必须动格式，须可迁移并单独说明）。  
4. 提供从 **LTS-1（1.6）** 与 **1.8** 到 2.2 的迁移指南。

**推荐对象**：单进程嵌入、可以接受单写者、需要可恢复备份和诚实隔离级别的后端。  
**不要在本版承诺**：多写者、复制、列存、集群。需要这些的人等后续 LTS，而不是把 2.2 当成「功能完工版」。

### LTS-2 承诺

- 不删除 2.2 `API.md` / `CLI-API.md` 中的稳定符号。  
- 不缩小已承诺的隔离语义：默认 `READ_COMMITTED`，显式 `REPEATABLE_READ` 为快照。  
- 第二进程打开同一目录仍然失败。  
- CLI 稳定子命令不改名。  
- `formatVersion` 若在 PATCH 中变化，必须带迁移。  
- 新功能进 **2.3+**，不进 `2.2.x`。

### 本版实际要做的事

1. 全量回归 FT-V20 与 FT-V21，外加一次备份演练脚本（全量、增量、差异、checksum 失败、坏 WAL）。  
2. `config.example.json` 只包含已冻结字段，与方案 §9 里尚未交付的集群/L3 字段区分开。  
3. `getCompatibilityInfo()`：`lts: true`，标识 `2.2`。  
4. README / Release 写明与 LTS-1 的并行窗口（建议 ≥ 12 个月，或至 LTS-3 发布后 6 个月，以 Release 为准）。  
5. 冻结 CLI 面。

### 不做

Geo、中文分词、Redis、列存、插件、多写者、savepoint、GraphQL、复制、Raft。这些都在更后面的非 LTS 版本，且默认不得破坏本契约。

## 3. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。这是 `@webofcat/jsonsqlite` 安装后读者看到的说明，不是本计划的缩写。

只改版本号、或只链到 `API.md` / `CLI-API.md` / Release，都不算完成。未参与实现的人只读这个文件，就要能判断该不该 pin 2.2、默认行为变不变、怎么迁移、本版不承诺什么。

写作要求：

- 与已经冻结的默认行为、API、CLI 一致。本版不增加功能，README 不得写成功能发布说明。
- 示例使用本仓库真实导出与命令（`create` / `open` / `getCompatibilityInfo`、`jsonsqlite`），可复制。标志位、默认值与实现一致。
- 文首写明版本号、**LTS-2**、单写者，以及生产上应该 pin 本线。
- 有迁移步骤就按可跟做的顺序列出。细节过长时可以链到迁移指南，但步骤本身必须在 README 里，不能只有链接。

本版 README 必须写清：

1. 版本行改为 **2.2.0**，标明 **LTS-2**。写明与 **LTS-1（1.6.x）** 的并行窗口（建议 ≥ 12 个月，或至 LTS-3 发布后 6 个月，以 Release 为准）。生产默认 pin 从 1.6 改到本线时，写明旧线仍收安全与正确性补丁到窗口结束。
2. `getCompatibilityInfo()` 的示例返回包含 `lts: true`，并能看出线是 `2.2`。说明各字段对选型的含义，不要只贴一个对象。
3. 单写者契约：第二进程打开同一目录仍然失败。默认隔离是 `READ_COMMITTED`，显式 `REPEATABLE_READ` 是快照。两种调用都给短例，写明调用方能观察到的差异。
4. `2.2.x` PATCH 的边界：不新增命令、不改默认值、不升 `formatVersion`。安全修复若必须动格式，须可迁移，并在 README 单独写迁移步骤。新功能进 **2.3+**，不进 `2.2.x`。
5. CLI：稳定子命令不改名。至少说明 `compat`、`version --json`（含 `lts: true` 与 `2.2`）、`config validate --file`（对照 `config.example.json`）。写明 PATCH 不再增加子命令。全局 flag、退出码若与 2.1 相同，明确写「不变」及当前值，避免读者去翻旧版 README。
6. 配置：`config.example.json` 只含已冻结字段。方案里尚未交付的集群 / L3 字段不在 example 中。写明未知危险键会被拒绝，以及拒绝时调用方看到什么。
7. 迁移：从 **1.6** 与 **1.8** 到 2.2。按打开路径、格式、加密、`rekey`、CLI 差异列出可执行步骤。默认仍是单写者。
8. 选型：适合单进程嵌入、接受单写者、需要可恢复备份和诚实隔离级别的后端。写明本版不承诺多写者、复制、列存、集群；需要这些的人等后续版本，而不是把 2.2 当成功能完工版。
9. dist-tag：`lts` 指向 2.2；`latest` 在 2.3 出现前也指向 2.2。写明 `npm install` 不带 tag 时在 2.3 发布前后分别会装到哪条线。
