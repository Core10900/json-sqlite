## 1. 为什么 2.2 可以当 LTS

同时满足四条才宣布长期稳定：

1. 新子系统已经在 2.0 和 2.1 落地，本版只冻结，不再引入分页、隔离、备份或告警的新行为。  
2. 方案 §12.2 在单写者契约下全绿：已提交可恢复、版本单调、提交后索引一致、备份校验失败则拒绝。  
3. 宣布之后，`2.2.x` PATCH 不新增命令、不改默认值、不升 `formatVersion`（安全修复若必须动格式，须可迁移并单独说明）。  
4. 提供从 **LTS-1（1.6）** 与 **1.8** 到 2.2 的迁移指南。

**推荐对象**：单进程嵌入、可以接受单写者、需要可恢复备份和诚实隔离级别的后端。  
**不要在本版承诺**：多写者、复制、列存、集群。需要这些的人等后续 LTS，而不是把 2.2 当成「功能完工版」。

### LTS-2 承诺

- 不删除 2.2 `API.md` / `CLI-API.md` 中的稳定符号。  
- 不缩小已承诺的隔离语义：默认 `READ_COMMITTED`，显式 `REPEATABLE_READ` 为快照。  
- 第二进程打开同一目录仍然失败。  
- CLI 稳定子命令不改名。  
- `formatVersion` 若在 PATCH 中变化，必须带迁移。  
- 新功能进 **2.3+**，不进 `2.2.x`。

### 本版实际要做的事

1. 全量回归 FT-V20 与 FT-V21，外加一次备份演练脚本（全量、增量、差异、checksum 失败、坏 WAL）。  
2. `config.example.json` 只包含已冻结字段，与方案 §9 里尚未交付的集群/L3 字段区分开。  
3. `getCompatibilityInfo()`：`lts: true`，标识 `2.2`。  
4. README / Release 写明与 LTS-1 的并行窗口（建议 ≥ 12 个月，或至 LTS-3 发布后 6 个月，以 Release 为准）。  
5. 冻结 CLI 面。

### 不做

Geo、中文分词、Redis、列存、插件、多写者、savepoint、GraphQL、复制、Raft。这些都在更后面的非 LTS 版本，且默认不得破坏本契约。
