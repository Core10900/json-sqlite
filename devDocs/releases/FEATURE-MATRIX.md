# JSONSQLite 设计能力采纳矩阵

> 基准：`devDocs/design/` + 已发布 **3.1.0** 代码（非 LTS；生产 pin 仍是 2.2，多写者 pin 仍是 2.5）  
> 用途：每项能力落在哪一版。生产 pin 与 LTS 资格见 [ROADMAP.md](./ROADMAP.md)  
> 状态图例：`✅ 已交付` · `📅 已排期` · `🔶 可选 / 实验` · `⛔ 明确不做` · `🔧 已有实现，未达设计`  
> 重排日期：2026-11-05。删除原 3.0–3.4 计划。未完成项在 **3.6.0 LTS-4** 冻结，不设 3.7。

---

## 0. 两个完工定义

**生产级（主推荐）= LTS-2（2.2）**：单写者、分页、备份链可恢复、WAL 失败关闭、RC 与 RR 诚实、运维闭环已在 2.1 浸泡。

**设计采纳** = 下表 `📅` 与 `🔧` 的补齐版本。集群在 **3.5** 浸泡，混沌三项全绿才发版；**3.6** 才冻结为 LTS-4。3.5 当天不能宣布 LTS。

**不做（⛔）**：

| 项 | 原因 |
|----|------|
| 完整 SQLite SQL 方言 | 方案：子集 + JSON 主查询 |
| 替代 Elasticsearch / 通用向量库 | 倒排 + 可选 vector 插件 |
| 替代 ClickHouse | 列存只做分析加速 |
| Advisor 强制依赖外部 LLM | 规则引擎；3.4 仅可选 hook，失败不拖垮查询 |
| 绝对性能「全面超越 SQLite」 | 2.0 公布自身 §12.3 包络 |

## 12. 2.5 已有能力、3.x 才补到设计

这些行不重复上表的排期，只固定「现在库里有什么、哪一版才算补完」。

| 现有行为 | 补完版本 | 补完标准 |
|----------|----------|----------|
| JSONPath 只取字段 | 3.0 | 过滤走安全 AST，危险语法拒绝 |
| 超时在查询返回后检查 | 3.0 | 扫描中途取消，不返回部分成功 |
| chunk 切段后仍攒齐再排序 | 3.0 | 与非 chunk 结果一致 |
| TreeIndex 为排序数组 | 3.1 | B+Tree，范围不是线性扫键 |
| Geo 遍历全部点 | 3.1 | 索引裁剪包围盒外的文档 |
| 列文件是 JSON 数组 | 3.1 | 数值差分/变长整数，字符串字典，hybrid |
| 压缩按类型启发式选择 | 3.1 | 采样窗口比压缩比，含 front-coding |
| 分层是内存拷贝 | 3.1 | 温/冷压缩，外部目录故障不毁热数据 |
| 备份链整段重放 | 3.2 | 可停在时间戳 |
| 时间旅行无保留窗、回滚无确认 | 3.2 | 默认 7 天；无确认不改数据并拒绝 |
| AutoTune 只建议或创建索引 | 3.2 | 缓存与压缩可灰度，失败回滚 |
| 质量只有完整度和唯一性 | 3.2 | 五项分数和建议；建议不写库；`autoFix` 不自动跑 |
| 流处理是进程内窗口；推送是 SSE | 3.2 | 管道 + WebSocket（含指标事件）；SSE 保留 |
| 指标只有累计次数和慢查询列表 | 3.2 | QPS、p50/p95/p99、锁等待、WAL 字节；`response_time` 告警 |
| HTTP 只有 `POST /query` | 3.4 | REST 文档读写委托现有引擎 |
| 存储建议尚未包含直方图和 compressed | 3.1 | 基数、嵌套深度、过滤字段直方图；四种模式 |
| Admin 单页 | 3.2 | 六个路径和分段计划 |
| 插件函数只活在进程内 | 3.2 | 磁盘入口，抛错隔离 |
| vector / S3 是 stub | 3.4 | 真实命中 / 真实读写 |
| 性能包络 N=2000 | 3.2 | 100 万文档公布包络；未达标写进 Release |
