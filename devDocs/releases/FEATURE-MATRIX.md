# JSONSQLite 设计能力采纳矩阵（至产品完工）

> 基准：`devDocs/design/` 四份文档 + 已发布 **1.6.0**  
> 用途：回答「做到哪一版算全部功能」；与 [ROADMAP.md](./ROADMAP.md) 配套  
> 状态图例：`✅ 已交付` · `📅 已排期` · `🔶 可选包/实验` · `⛔ 明确不做（产品边界）`

---

## 0. 「全部功能」的定义

**产品完工（Vision Complete）= 本矩阵中所有 `📅` 项在标注版本交付，且无残留未解释的大纲条目。**

对应发版标签：**`3.0.0`（LTS-3）**。此前的 **LTS-1（1.6）** / **LTS-2（2.2）** 是可长期 pin 的阶段性稳定线，不代表大纲勾满。

**不做为硬目标（⛔）**——写进方案边界，不进发版验收：

| 项 | 原因 |
|----|------|
| 完整 SQLite SQL 方言兼容 | 方案：子集 + JSON 主查询 |
| 替代 Elasticsearch / 通用向量库产品 | 倒排基础 + vector **插件**即可 |
| 替代 ClickHouse 级数仓 | 列存仅热表分析加速 |
| Advisor 强制依赖外部 LLM/GPT | 可提供可选 hook；核心用规则引擎 |
| 绝对性能「全面超越 SQLite」宣传数字 | 方案风险表；以自身 baseline 为准 |
