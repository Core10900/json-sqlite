# 2.5 → 3.6 与 3.5 → 3.6 迁移指南

> 随 **3.6.0 LTS-4** 发布。3.6 不增加功能，默认不改变 2.5 的单写者行为。  
> 本文件在 3.6 开发完成时与实现核对。命令名以当时的 `packages/core/README.md` 为准；若实现时命令与下表不同，改本文件，不改已经冻结的 2.5 行为。

## 1. 从 2.5 升级

1. 安装 `@webofcat/jsonsqlite@3.6.0`（或 dist-tag `lts` / `lts-4`，以 Release 宣布的指向为准）。  
2. 用原 `storagePath` 打开数据库，或不写复制、集群相关键直接 `open`。  
3. 打开之后确认：写者模式仍是 `single`，复制关闭，集群关闭。需要多写者时沿用 2.5 的 `writers: 'multi'`，这不是升级的必选项。  
4. 需要 3.0–3.5 的能力时，按 `packages/core/README.md` 逐项打开。每一项都是 opt-in。  
5. 若必须走 `migrate`，使用 README 中的迁移命令。失败时不得留下半份目标目录。

不要求在这一步启用列存、Redis、复制、GraphQL 或集群。

## 2. 从 3.5 升级

1. 安装 `3.6.0`。  
2. 直接打开原目录。磁盘 `formatVersion` 与 3.5 最后一个补丁相同。  
3. 原来关闭的复制和集群保持关闭。原来显式打开的开关保持打开，语义不缩小。  
4. 不需要再跑一遍数据迁移。

## 3. 回退

3.6 不升格式。若现场没有打开过 3.1 及以后的新存储文件，数据目录可以继续用 2.5 打开。一旦写入了 3.1 的列编码、3.3 的复制日志或 3.5 的集群元数据，回退到 2.5 之前先按 3.6 README 导出不依赖这些文件的文档数据。不要把新格式目录直接交给 2.5 进程。
