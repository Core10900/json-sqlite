# JSONSQLite v3.6.0 性能包络（LTS-4）

> 机器：本机发版跑数 · Node.js v22.22.0 · `syncMode: 'none'` · **LTS-4**  
> 相对 [v3.2.0 性能包络](../v3.2.0/性能包络.md) 的复测。  
> 本版**不增加功能、不升磁盘格式**；下列为冻结前的热路径优化与复测结果。数字只写在本文件，安装包 README 引用本路径。

## 本版热路径优化（相对 3.2 / 3.5）

| 项 | 说明 |
|----|------|
| 批量回表 | 索引命中后走 `DocumentStore.getByIds`：按页分组解码、批量期间 pin 页避免 LRU 抖动；工作集全驻留时单遍查找，不做二次「是否全热」扫描 |
| id→page | 运行时用 V8 `Map`（`idPageMaps`）；`pages.json` 仍持久化 `Record`，读写路径保持同步 |
| 覆盖索引 | 单字段等值/范围且无 `orderBy`/投影时，跳过对已索引谓词的二次 `match` |
| 点查热路径 | 去掉每次查询的 `process.memoryUsage()`（大堆上可达数毫秒）；树/对象索引 `stats()` 结果缓存，避免 O(n) 扫叶 |
| 大样本 bench | `pageSize: 8192`、`maxResidentDocs: N` 覆盖工作集；10 万级过滤按方案 §1.3 取 **P95**（先预热再采样） |

默认 `pageSize` / `maxResidentDocs` **不变**（仍为 32 / 256）。百万级包络刻意放大驻留预算，对应方案「单机 SSD + 热缓冲」假设，不是改默认配置。

## 运行说明

```bash
BENCH_N=1000000 pnpm --filter @jsonsqlite/bench start
# 点查 P99 / 过滤 P95 另见：
node apps/bench/p99-conc.mjs
```

大样本：事务分块写入、更大 `pageSize` / `maxResidentDocs`，并跳过整库 `rebuildIndexes`（不是 §1.3 场景）。

## 实测（100 万文档量级）相对方案 §1.3

| 场景 | 实测 | §1.3 目标 | 是否达到 |
|------|------|-----------|----------|
| 等值点查（有索引） | 按 `name` P99 **0.015 ms**；按 `_id` P99 **0.001 ms** | P99 ≤ 1ms | **达到** |
| 10 万级过滤（`age` 树索引，约 10 万命中） | P95 **31.9–38.6 ms** | P95 ≤ 50ms | **达到** |
| 10 万条批量写入 | **436 ms** | ≤ 3s（不开加密） | **达到** |
| 范围查询（tree，`age` 10–20） | **40 ms** | 优于全表扫描 | **达到** |
| 全文（inverted `$contains`，limit 20） | **179 ms** | 可用 | **达到** |
| 并发读写 | **20 ms**（20 读 + 20 写） | 单机不崩溃 | **达到** |
