# v3.6.0 npm 发布说明

> 包名：`@webofcat/jsonsqlite`  
> 功能与测试：[开发计划.md](./开发计划.md) · [功能测试计划.md](./功能测试计划.md) · [迁移指南.md](./迁移指南.md)  
> **LTS-4。** 本版第一次移动 `lts`。`latest` 也要指到 3.6.0。两个标签一起改，缺一个都算没发完。

不带版本号的 `npm view @webofcat/jsonsqlite` 读的是 `latest`。2.5.0 只用 `lts-3` 发布时，这条命令一直显示 2.4.0。3.6 若只加 `lts-4`、不移动 `latest`，会再次出现同样的结果。

`latest` 是最新发布。`lts` 从这一版起是新的生产 pin。`lts-2` 和 `lts-3` 留在原来的线上，给仍要单写者旧契约或多写者旧契约的人。

---

## 1. 发布后的标签

发布前先执行 `npm view @webofcat/jsonsqlite dist-tags --json`，记下当时的值。

| 标签 | 发布前 | 发布后 |
|------|--------|--------|
| `latest` | 3.5.x | **3.6.0** |
| `lts` | 2.2.0 | **3.6.0** |
| `lts-2` | 2.2.0 | **2.2.0**（不改） |
| `lts-3` | 2.5.0 | **2.5.0**（不改） |
| `lts-4` | 不存在 | **3.6.0**（新增） |

不删除 `lts-2` 和 `lts-3`。不把 2.2 或 2.5 的 `latest` 改回旧版。

---

## 2. 先改安装包里的文字，再 publish

这些文件打进 tarball 或被 `npm view` 直接显示。publish 之后再改，已经发出的 3.6.0 不会变。

| 位置 | 要求 |
|------|------|
| `packages/core/package.json` 的 `version` | `3.6.0` |
| 同文件的 `description` | 含 `3.6.0`、`LTS-4`、默认单写者、复制关、集群关 |
| `packages/core/README.md` | 文首版本是 3.6.0、LTS-4。写明不带 tag 的安装得到 `latest`（3.6.0），默认仍是单写者、复制关、集群关。`lts` 与 `lts-4` 都是 3.6。`lts-2` 仍是 2.2，`lts-3` 仍是 2.5。`getCompatibilityInfo()` 的示例是 `lts: true`、`ltsLine: '3.6'` |
| `packages/core/config.example.json` | 与 3.5 最后一个补丁的默认开关相同。本版不新增会默认打开的键 |
| 仓库根 `README.md`、`CHANGELOG.md` | 与上面同一套标签句子。迁移步骤与 `迁移指南.md` 一致 |

`description` 使用这一句：

```text
JSON-native embedded database for Node.js — 3.6.0 LTS-4 (default single-writer; replication off; cluster off)
```

不要写新的子系统，不要把 WASM 写路径补进承诺，不要出现 3.7。

## 3. 发布命令

在 `packages/core` 执行。仓库根是 `"private": true`，不能在根目录 publish。

```bash
pnpm publish --access public
npm dist-tag add @webofcat/jsonsqlite@3.6.0 lts
npm dist-tag add @webofcat/jsonsqlite@3.6.0 lts-4
```

第一行会把 `latest` 指到 3.6.0。后两行才移动生产 pin 并建立 LTS-4。三行都要执行。`prepublishOnly` 会先 build 再跑测试；测试失败就不要绕过它发版。

不要只执行后两行。不要用 `--tag lts-4` 代替第一行，否则 `latest` 会留在 3.5。

---

## 4. 发出后立刻核对

```bash
npm view @webofcat/jsonsqlite version
npm view @webofcat/jsonsqlite description
npm view @webofcat/jsonsqlite dist-tags --json
```

通过标准：

- `version` 是 `3.6.0`。若仍是 3.5.x，就是 `latest` 没动。
- `description` 含 `3.6.0` 和 `LTS-4`。
- `latest`、`lts`、`lts-4` 都是 `3.6.0`。
- `lts-2` 仍是 `2.2.0`，`lts-3` 仍是 `2.5.0`。

标签不对时用 `npm dist-tag add` 补，不要为了改标签再 publish 一次。例如 `latest` 仍是 3.5.x：

```bash
npm dist-tag add @webofcat/jsonsqlite@3.6.0 latest
```

四项都符合之前，不要在 GitHub Release 里写「已发布」。Release 标题含 LTS-4，并写明默认不启用复制和集群。

## 5. 3.6.x 补丁

补丁只修正确性和安全。不新增命令，不改默认值，不升 `formatVersion`，不加复制语义或选主。

每次 3.6 补丁同时移动三个标签：

```bash
pnpm publish --access public
npm dist-tag add @webofcat/jsonsqlite@<补丁版本> lts
npm dist-tag add @webofcat/jsonsqlite@<补丁版本> lts-4
```

`lts-2` 和 `lts-3` 不动。核对时 `npm view @webofcat/jsonsqlite version` 必须是该补丁版本。
