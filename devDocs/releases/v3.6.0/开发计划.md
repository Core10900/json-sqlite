# JSONSQLite v3.6.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**设计完工长期稳定线（LTS-4）**  
> 前置：**3.5.0** 的混沌三项已绿，并且经过浸泡（`3.5.x` 只修缺陷，建议至少一个补丁周期）  
> **LTS：是 —— LTS-4**  
> 兼容：相对 3.5 为 **MINOR**。**本版不增加功能**，不升磁盘格式，不改变默认开关

## 1. 为什么 3.6 可以当 LTS

3.0 到 3.5 把方案里排进路线的未完成项都落地了。3.5 是集群的第一次完整实现，不能在同一版上宣布长期稳定。3.6 只冻结 3.5 已经跑绿的契约。

| 线 | 谁应该 pin |
|----|------------|
| **LTS-2 = 2.2.x** | 只要单写者、且不需要 3.x 能力 |
| **LTS-3 = 2.5.x** | 只要同一台机器的多进程写 |
| **LTS-4 = 3.6.x** | 需要这条完工线。默认仍是单写者，复制关闭，集群关闭 |

LTS-4 承诺：

- 默认配置的单机正确性不低于 LTS-3 的默认单写者模式。  
- 3.0 的查询语义、3.1 的默认关闭存储开关、3.3 的「不自动选主」、3.4 的 Quorum 错误码和接入层、3.5 已通过的选主 / 分区 / rebalance / 跨机锁，在 `3.6.x` PATCH 中不缩小。  
- PATCH 不新增命令，不改默认值，不升 `formatVersion`。  
- WASM 在 3.5 以只读实验包发布。3.6 维持该边界，不把写路径补进承诺。  
- 与 LTS-2、LTS-3 并行维护。安全补丁按「单机是否受影响、复制是否受影响、集群是否受影响」分别评估。

本版交付物是回归、迁移说明（2.5 → 3.6，以及 3.5 → 3.6）、`lts: true` 且线名为 `3.6`、冻结 CLI 面。

### 不做

任何 3.5 没有的子系统。不实现完整 SQL 方言、通用向量库、通用数仓、多语言 TCP。不发布 3.7 计划。

## 2. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。3.6 不增加功能。只改版本号不算完成。

写作要求：

- 与 3.5 已经跑绿并在本版冻结的契约一致。不在 README 里扩写 3.5 没有的行为。
- 读者要能决定留在 2.2、2.5 还是升到 3.6，并知道升级后默认仍是单写者、复制关、集群关。
- `getCompatibilityInfo()` 与 `version --json` 的示例可复制，字段与实现一致。
- 文首写明 **3.6.0、LTS-4**。这是设计功能完工后的长期稳定线。

本版 README 必须写清：

1. 三条线的分工：
   - **LTS-2 = 2.2.x**：单写者生产，不需要 3.x 能力就留在这里。
   - **LTS-3 = 2.5.x**：同一台机器上的多进程写。
   - **LTS-4 = 3.6.x**：3.0–3.5 已交付能力的冻结线。默认不打开这些能力。
2. 承诺边界：默认 single、复制关、集群关的正确性不低于 LTS-3 默认模式。已文档化的查询、存储开关、复制、Quorum、接入层和 3.5 混沌语义在 PATCH 中不缩小。PATCH 不加命令、不升格式。
3. 迁移 **2.5 → 3.6**：直接打开，或以文档中的 migrate 打开。每一步之后默认写者模式仍是 single，复制和集群仍关。需要哪一项必须显式打开，并链到对应版的说明。本版 README 保留足够上下文，使读者不必先读 3.0–3.5 的计划。
4. 迁移 **3.5 → 3.6**：不改数据格式。若 3.5 有未发布的实验开关，3.6 的行为与 3.5 最后一个补丁相同。
5. `getCompatibilityInfo()` 返回 `lts: true`，线名为 `3.6`。`version --json` 能区分 `ltsLine: '3.6'`。这些字段和包版本字符串不是同一个数。
6. CLI 面冻结，包含 3.0–3.5 已经进入稳定帮助的命令。列出本线读者会用的稳定入口，并写明 PATCH 不新增子命令。集群命令仍只在开关打开时按 3.5 的帮助规则出现。
7. dist-tag：`lts-2` 继续指向 2.2，`lts-3` 继续指向 2.5，`lts-4` 指向 3.6。宣布本版时 `lts` 从 2.2 改指向 3.6。`npm install` 不带 tag 时是否跟着 `latest` 走，要在同一段写明 `latest` 不是「自动打开集群」的意思。
8. 性能：引用 3.2 的包络文件。3.6 不重新许诺大纲里的绝对数字。若 3.2 有未达标项，这里保持同一说法。
9. 明确不在本版：新存储格式、新复制语义、新选主规则、完整 SQL 方言、通用向量库、通用数仓、多语言 TCP、WASM 写路径。
