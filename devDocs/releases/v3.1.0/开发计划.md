# JSONSQLite v3.1.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**复制硬化**——Quorum、读写分离、冷存储可用、三节点手册  
> 前置：**3.0.0** 异步复制雏形  
> **LTS：否**（浸泡；冻结见 **3.2 = LTS-4**）  
> 兼容：相对 3.0 为 MINOR。不开启复制时单机契约不变  
> 路线图：[../ROADMAP.md](../ROADMAP.md)

---

## 1. 目标

1. Quorum 可配置。达不到确认数时写入失败，错误码稳定，主库不把未确认写入报告为已复制。  
2. 读请求可路由到从库，写只到主。从库滞后超过阈值时，读路由有文档化的策略（失败或退回主）。  
3. 三节点手册：启动、看滞后、停一个从、手动提升。步骤可被测试脚本或检查清单复述。  
4. S3（或等价对象存储）冷存储插件从 stub 变为可读写的示例，失败时热数据仍可查。  
5. 仍然**没有**自动选主。手动 promote 的危险操作写入审计。

### 不做

Raft、自动 rebalance、跨机锁、GraphQL、WASM。

## 3. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。本版把复制从雏形补到可操作的 Quorum、路由和冷存储，只改版本号、或把手动提升写成自动选主，都不算完成。

写作要求：

- 与已测的错误码、滞后策略、审计行为一致。不开启复制时，单机章节仍成立。
- 读者要能配置 Quorum、看懂写失败、把读路由到从库、按步骤跑通三节点，并知道冷存储故障后热数据还在。
- 示例可复制。稳定错误码用实现中的名字。手册步骤与测试或检查清单一致，README 不另写一套。
- 文首写明 **3.1.0、非 LTS**。复制的生产 pin 仍不是本版，冻结在 **3.2（LTS-4）**。仍然没有自动选主。

本版 README 必须写清：

1. Quorum：确认数如何配置，默认是多少。达不到确认数时写入失败的稳定错误码，调用方能否重试。主库不把未确认写入报告为已复制：写明状态字段在失败时的取值，避免读者用「主库本地已提交」判断从库。
2. 读写分离：读请求如何路由到从库，写为什么只到主。从库滞后超过阈值时的策略是失败还是退回主，默认是哪一种、如何修改、两种策略下调用方看到的结果。给一条读和一条写的示例。
3. 三节点手册摘要必须可跟做：启动、看滞后、停一个从、手动提升。每步的命令、预期输出、失败时停止而不是继续。promote 是危险操作，写入审计；写明审计里能看到的操作者、时间和角色变化。没有自动选主，提升不会在主宕机时自己发生。
4. 冷存储：S3（或等价对象存储）插件从 2.3 的 stub 变为可读写示例。写明安装或注册、配置、写入后读回。插件或对象存储失败时，热数据仍可点查，给失败后的查询示例，并写明冷层上尚未取回的数据不能假装还在热层。
5. CLI：`replica status` 含 quorum 与角色。列出字段表（名称、含义、正常与异常时的典型值）。不要只写「status 变详细了」。
6. 不开启复制时，单机契约相对 3.0 不变。README 保留单机默认路径，避免整篇只剩集群步骤。
7. 明确不在本版：Raft、自动 rebalance、跨机锁、GraphQL、WASM、自动选主。
