# JSONSQLite v3.1.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**索引与存储算法补齐**（B+Tree、空间索引、列编码、hybrid、压缩选算法、分层压缩）  
> 前置：**3.0.0** 的查询等价测试已绿  
> **LTS：否**  
> 兼容：相对 3.0 为 **MINOR**。不写新配置时，打开 2.5 / 3.0 库的读写结果与 3.0 一致。索引分段格式变化时启动重建，不要求迁移文档页

## 1. 目标

2.3 已经有列文件、分层旗标、delta/字典/RLE/gzip 和线性 Geo 索引。2.5 的 `TreeIndex` 仍是排序数组。本版把方案 §4、§6 里这些算法补上，并继续默认关闭新存储格式。

1. **B+Tree** 替换有序索引的内存结构。order 默认 128。存 `key → _id[]`，`search` 与 `rangeSearch` 为 O(log n)。分段落盘，`index compact` 之后查询不变，reopen 仍可用。  
2. **GeoIndex** 用网格或 R 树回答 `$geoWithin`。有索引时不得先读出全部点再过滤。未建索引时仍允许扫描，`explain` 标明扫描。  
3. **中文分词**可插拔。不传模块时 `open` 不加载外部包。传入的模块抛错时，引擎仍能 open，分词查询返回稳定错误，其余查询可用。  
4. **列编码**：数值列差分 + 变长整数，字符串列字典。投影只读请求的列。列文件损坏或未就绪时退回文档页，退回不是查询错误。WAL 仍是提交事实。  
5. **hybrid**：指定热字段走列存，其余嵌套字段留在文档页。结果与纯文档模式一致。  
6. **自适应选择**只在配置打开后给出建议，不自动改已有表。输入是字段基数、嵌套深度，以及 Monitor 记下的过滤字段直方图（本版起查询记录被过滤的字段名，不记录文档内容）。输出是 `document`、`columnar`、`hybrid`、`compressed` 之一。`compressed` 表示超过压缩阈值的大字段或大文档走压缩块，查询结果与 document 模式一致。调用方执行显式命令后才切换。  
7. **压缩**：在 2.3 的四种算法上增加 front-coding。采样窗口比较压缩比后再写入块头里的算法名。reopen 按块头解压。与加密叠加的顺序有测试。  
8. **分层**：温层轻量压缩，冷层 gzip 或 zstd。后台迁移，不在写调用里完成。冷数据可迁到配置的外部目录。外部目录不可用时热数据仍可点查。  
9. 缓存热 key 在 L1 提升；预取失败退回按需读页。L3 Redis 不在本版。  
10. 倒排索引的停用词表可配置。不配置时保持现有的中英停用词。改表之后重建倒排索引，查询结果使用新表。空表表示不丢弃任何词。

### 成功标准

- 默认配置通过 3.0 回归。  
- 打开 B+Tree 的范围查询与排序数组实现的 `_id` 集合一致，并有比较次数或节点访问次数的断言，证明不是线性扫键。  
- 列存投影的文件读取数少于 `SELECT *`。  
- 压缩 round-trip 含加密。外部冷目录失败后热文档仍可按 `_id` 读到。  
- FT-V31-* 全绿。Release 标明 **非 LTS**。

### 不做

复制、Quorum、Redis、GraphQL、可用向量检索、可用 S3、集群、WASM。

## 3. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。只改版本号、或把默认打开写成已经换了存储格式，都不算完成。

写作要求：

- 说明文字用中文。本版改到的 `packages/core/README.md` 与仓库根 `README.md` 都用中文写。命令、配置键、错误码和代码示例保持原文。用英文段落代替中文说明不算完成。
- 与默认关闭、退回文档页、外部目录失败后的查询结果一致。
- 读者要能打开 2.5 库且不写新键，并知道每个新键打开的是哪一种文件。
- 示例可复制。没有实测的加速倍数不要写进正文。
- 文首写明 **3.1.0、非 LTS**。

本版 README 必须写清：

1. 默认路径：不写新配置时行为与 3.0 一致，2.5 库能打开。索引分段若重建，写明重建发生在 open，文档页不迁。
2. B+Tree：order 的配置名和默认 128。范围查询如何确认走了树。`index compact` 的命令。reopen 后范围结果不变。
3. Geo：建索引的命令，一条 `$geoWithin` 示例。无索引时 `explain` 标明扫描。
4. 分词：不传模块时 open 不导入外部包。模块失败时的错误码，以及同一库上的点查仍然成功。
5. 列存与 hybrid：按表打开的配置。写路径先落 WAL。投影少读哪些文件。列文件未就绪时退回文档页，退回不是错误。
6. `storage advise` 只输出建议。写明输入是基数、嵌套深度和过滤字段直方图，输出四种模式及 `compressed` 的含义。自动改存储模式的命令如果没有实现，README 不出现「会自动切换」。
7. 压缩：front-coding 用在哪类数据，采样窗口如何选算法，块头字段名，reopen 如何识别。与加密叠加的顺序，round-trip 失败时调用方看到的错误码。
8. 分层：温层和冷层的算法，外部目录配置。目录不可读时热文档点查的示例。
9. 热 key 与预取的计数在哪个 API。预取失败退回按需读，退回不是错误。  
10. 停用词：配置项的名字、默认词、空表的含义、修改后需要重建倒排索引。  
11. 明确不在本版：Redis、复制、S3 实际上传、可用向量检索、GraphQL、集群。

## 5. 风险

| 风险 | 缓解 |
|------|------|

| 列编码与加密顺序错误 | round-trip 测试覆盖两种顺序 |
