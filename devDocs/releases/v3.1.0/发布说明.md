# v3.1.0 npm 发布说明

> 包名：`@webofcat/jsonsqlite`  
> 功能与测试：[开发计划.md](./开发计划.md) · [功能测试计划.md](./功能测试计划.md)  
> **非 LTS。** 本文件只管注册表标签和安装包里的文字。功能做完但标签没核对，这一版不算发出去。

不带版本号的 `npm view @webofcat/jsonsqlite` 读的是 `latest`，不是仓库里的最高版本号。2.5.0 只用 `lts-3` 发布时，这条命令一直显示 2.4.0。

`lts` 是生产 pin。`latest` 是当前发布的最新版本。这一版不动 `lts`，但必须把 `latest` 移到 3.1.0。

---

## 1. 发布后的标签

发布前先执行 `npm view @webofcat/jsonsqlite dist-tags --json`，记下当时的值。

| 标签 | 发布后 |
|------|--------|
| `latest` | **3.1.0** |
| `lts` | 与发布前相同，应为 **2.2.0** |
| `lts-2` | 与发布前相同，应为 **2.2.0** |
| `lts-3` | 与发布前相同，应为 **2.5.0** |

不新增 `lts-4`。不删除已有标签。

---

## 2. 先改安装包里的文字，再 publish

这些文件打进 tarball 或被 `npm view` 直接显示。publish 之后再改，已经发出的 3.1.0 不会变。

| 位置 | 要求 |
|------|------|
| `packages/core/package.json` 的 `version` | `3.1.0` |
| 同文件的 `description` | 含 `3.1.0`、`not LTS`、生产 pin 仍是 2.2、新存储默认关闭 |
| `packages/core/README.md` | 文首版本是 3.1.0、非 LTS。写明不带 tag 的安装得到 `latest`（3.1.0）。新存储不写配置时行为与 3.0 一致。`lts` / `lts-2` 是 2.2，`lts-3` 是 2.5 |
| `packages/core/config.example.json` | 含本版新增且默认关闭的存储字段。此文件在 `files` 里，会进安装包 |
| 仓库根 `README.md`、`CHANGELOG.md` | 与上面同一套标签句子 |

`description` 使用这一句：

```text
JSON-native embedded database for Node.js — 3.1.0 storage algorithms (not LTS; production pin remains 2.2; new storage default off)
```

不要出现 LTS-4、设计完工、Vision Complete。不要把 B+Tree、列存或分层写成默认已经打开。

---

## 3. 发布命令

在 `packages/core` 执行。仓库根是 `"private": true`，不能在根目录 publish。

```bash
pnpm publish --access public
```

不要加 `--tag`。默认就会把 `latest` 指到 3.1.0。`prepublishOnly` 会先 build 再跑测试；测试失败就不要绕过它发版。

```bash
# 不要这样发 3.1.0
pnpm publish --access public --tag lts-3
```

---

## 4. 发出后立刻核对

```bash
npm view @webofcat/jsonsqlite version
npm view @webofcat/jsonsqlite description
npm view @webofcat/jsonsqlite dist-tags --json
```

通过标准：

- `version` 是 `3.1.0`。若仍是 3.0.x，就是 `latest` 没动。
- `description` 含 `3.1.0`。
- `latest` 是 `3.1.0`。`lts`、`lts-2`、`lts-3` 的版本号与发布前相同。

没通过时只改标签，不要为了改标签再 publish 一次：

```bash
npm dist-tag add @webofcat/jsonsqlite@3.1.0 latest
npm view @webofcat/jsonsqlite version
```

三条命令都符合上一节之前，不要在 GitHub Release 里写「已发布」。

## 5. 3.1.x 补丁

补丁只修正确性和安全，不新增命令，不改默认值，不把新存储改成默认打开。

- 当时没有更高的 3.x 占据 `latest`：补丁版本发布后，`latest` 改为该补丁。
- 3.2 或更高版本已经是 `latest`：只发布 `3.1.x`，不移动 `latest`，也不移动任何 `lts*`。
- 补丁的 `description` 和 `packages/core/README.md` 写该补丁的版本号，并保持非 LTS、新存储默认关闭。
