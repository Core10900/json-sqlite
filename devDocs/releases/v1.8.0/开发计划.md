## 1. 背景与目标

1.7 补齐体验后，瓶颈会回到设计 §1.3 的性能门槛与存储层「全表进内存」限制。1.8 目标是：

1. **大表可开**：索引落盘，减少冷启动全量 rebuild  
2. **查询可快**：可选 L2 缓存、压缩、热区识别（单机，非 Redis 必选）  
3. **指标可证**：bench 对齐技术实现方案 §1.3 / §12.3，阈值防回退  
4. **2.0 可接**：热/冷分层与轻量压缩作为 **默认关闭** 的实验能力，不承诺格式冻结到 2.0  

```text
1.7  体验补齐
1.8  性能 / 索引落盘 / 压缩与分层雏形 / CI   ← 本文
2.0  多写者 / 列存正式 / 插件 / 复制
```

### 1.8 成功标准

1. 索引元数据 + 分段落盘；大表 reopen 耗时可观测且低于「全量 rebuild」基线  
2. 可选 `l2Cache`（进程内）；命中率进入 metrics  
3. 可选文档/集合级压缩（阈值阈值以上）；加密路径仍正确  
4. `apps/bench`：点查 / 范围 / 批量写入 / 并发读 产出可比报告；关键阈值可进 CI  
5. GitHub Actions：Node 20 + 22 × Ubuntu（需仓库 token 具备 `workflow`）  
6. FT-V18-* 全绿；回归含 1.6/1.7 关键路径  

### 1.8 不做

| 项 | 留给 |
|----|------|
| 多进程多写 | 2.0 |
| 正式列存引擎与跨版本格式承诺 | 2.0 |
| Redis L3 强依赖 | 保持 optional / 文档示例 |
| Raft / 分片 | 2.0 原型 |

## 2. 需求摘要

| ID | 需求 | 目标行为 |
|----|------|----------|
| V18-IDX-1 | 索引持久化 | 启动加载分段；损坏可 rebuild + doctor 报告 |
| V18-IDX-2 | 增量落盘策略 | 与 WAL/提交语义一致；崩溃可恢复 |
| V18-CACHE-1 | L2 缓存 | 配置开关；失效与写路径联动 |
| V18-STOR-1 | 压缩 | 大文档/冷集合可选 gzip 等；透明读写 |
| V18-STOR-2 | 热冷雏形 | 访问计数 → tier 标记；冷数据延迟加载（实验旗标） |
| V18-PERF-1 | Bench 套件 | 对齐设计场景；可写 baseline |
| V18-PERF-2 | 回归阈值 | CI 或 nightly：写入/点查不超过相对阈值 |
| V18-CI-1 | Actions | lint + build + test 矩阵 |
| V18-SQL-1 | 可选小扩展 | 如简化 `GROUP BY` 或更清晰 `SQL_*` 错误（不引入方言膨胀） |
| V18-DOC-1 | 性能手册 | README / API：何时开 L2、压缩、分层风险 |
| V18-CLI-1 | CLI-API 适配（1.8） | 见 **§2.1**；[../CLI-EVOLUTION.md](../CLI-EVOLUTION.md) |

### 2.1 CLI-API 适配（1.8）

| ID | 命令 / 改动 | 说明 |
|----|-------------|------|
| V18-CLI-A | `index rebuild [table]` | 落盘索引损坏后重建 |
| V18-CLI-B | `doctor` 扩展检查项 | 索引落盘 / 压缩 / tier 摘要（`--json`） |
| V18-CLI-C | `vacuum --compress`（或等价 flag） | 与压缩能力对齐 |
| V18-CLI-D | `stats --json` 字段 | 含 L2 命中、tier（若开启） |
| V18-CLI-E | `CLI-API.md` 1.8 增补 | 文档 + help |
