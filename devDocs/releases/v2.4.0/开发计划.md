# JSONSQLite v2.4.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**单机多写者（opt-in）**  
> 前置：建议在 **2.2 LTS-2** 已对外提供之后再合入；实现上依赖 2.0 分页与 2.1 恢复语义  
> **LTS：否**（并发模型首发，必须浸泡；冻结见 **2.5 = LTS-3**）  
> 兼容：相对 2.3 为 MINOR **当且仅当默认仍是单写者**。多写者必须显式开启。开启后的锁语义以本版 RFC 为准

## 1. 目标

方案允许在单机正确性之后做多进程写，并要求冲突可见、禁止静默损坏。本版只做**同一台机器上的多进程**：

1. 默认 `writers: 'single'`，行为与 LTS-2 相同，第二进程被拒绝。  
2. `writers: 'multi'` 时有书面锁协议：锁粒度、持有者崩溃后的恢复、可重试错误码。  
3. 两个进程同时提交冲突写：一方成功，另一方得到稳定错误，已成功的文档不丢。  
4. `SERIALIZABLE` 只在 multi 模式下提供；冲突升级可复现。single 模式仍拒绝 SER。  
5. 死锁：等待图成环时一方回滚并返回稳定错误码。  
6. savepoint：显式 API，默认事务仍是一层。回滚 savepoint 不影响外层已暂存的修改。  
7. 故障注入：写进程在 fsync 前后被杀死，重启后已提交在、未提交不在，索引与数据一致。  
8. 不包含复制、选主、跨机锁。

### 成功标准

- single 模式跑通 FT-V22。  
- multi 模式的冲突、死锁、崩溃注入全绿，且测试时长内无静默丢写。  
- RFC 在合并前冻结「崩溃后谁持有锁」。没有这份 RFC 不开工实现。

### 不做

异步复制、Quorum、Raft、自动分片。GraphQL 与多库管理不在本版。

## 2. 需求

| ID | 需求 |
|----|------|
| V24-RFC-1 | 锁协议与崩溃恢复 RFC |
| V24-CON-1 | 默认单写者不变 |
| V24-CON-2 | opt-in 多进程写；冲突错误可重试语义写进 API |
| V24-ISO-1 | multi 模式下的 SERIALIZABLE |
| V24-DLK-1 | 等待图死锁检测 |
| V24-TX-1 | savepoint |
| V24-CHAOS-1 | 双进程 + kill 注入 |
| V24-CLI-1 | 见下表 |

### CLI（2.4）

| ID | 命令 | 说明 |
|----|------|------|
| V24-CLI-A | open / 全局 flag `--writers single\|multi` | 默认 single |
| V24-CLI-B | `doctor` | 报告当前写者模式与锁持有者 |
| V24-CLI-C | 文档 | 写明 multi 不是 LTS，生产多写者等 2.5 |

## 4. 风险

| 风险 | 缓解 |
|------|------|
| 多进程损坏 | 默认关闭；注入测试是发版门禁 |
| 与分页锁交互 | RFC 写清页锁与文档锁的顺序，禁止未文档的锁升级 |
| 用户把 2.4 当生产 pin | Release 与 `lts: false` 写明等待 2.5 |
