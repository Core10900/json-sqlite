# 2.2 → 2.3，以及 1.8 `tiering` 怎么对上新布局

> 包：`@webofcat/jsonsqlite@2.3.0`（**非 LTS**）
> 生产不需要列存或插件时，继续 pin **2.2**。2.3 的默认 `open` 不改 2.2 库的行为。

`formatVersion` 仍是 2。2.2 的目录可以直接 `open`，不用 `migrate`。

## 1.8 实验旗标 → 2.3 热 / 温 / 冷

`tiering: true` 不是新布局。它仍表示 1.8 的行为：`close()` 时按 `tierColdAfter` 把文档扫进 `cold.jsonl`。2.3 默认 `tiering: false`。

对应关系：

| 旧 | 新 |
|----|----|
| `tiering: true` | 不用它打开新布局。新开关是 `storageTiers: true` |
| `tierColdAfter`（默认 0） | `coldAfter`（默认 0） |
| 无 | `warmAfter`（默认 1） |

可执行步骤：

1. 停掉占用目录的进程。`cp -R ./data ./data-backup`。
2. **仅当 1.8 开过 `tiering: true`。** 用 1.8 的二进制执行 `open({ storagePath, tiering: false })` 然后 `close()`，把 `cold.jsonl` 折回热数据。1.6 没有这个文件，跳过。2.3 对 format 1 会抛 `MIGRATION_REQUIRED`。
3. 若目录还是 format 1，按 [2.2 迁移指南](../v2.2.0/迁移指南.md) 迁到新目录。format 2 的 2.2 库跳过这一步。
4. 安装 2.3 之后这样打开：

```ts
import { open } from '@webofcat/jsonsqlite';

const db = await open({
  storagePath: './data-v2',
  tiering: false,
  storageTiers: true,
  coldAfter: 0,
  warmAfter: 1,
});
```

冷层要接到自己的存储时，再 `registerPlugin({ kind: 'storage', name, version, putCold })`。没有插件时冷、温文件在 `collections/<表>/tiers/cold.jsonl` 和 `warm.jsonl`。迁移在后台跑，`insert` 不会等它。

S3 的可用上传不在本版。`createS3Stub()` 只会把 `putCold` 记一次调用。
