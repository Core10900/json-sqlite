# JSONSQLite v2.3.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**存储与查询增强**（列存、分层、压缩、插件）  
> 前置：**2.2.0 LTS-2 已宣布**。生产默认 pin 继续是 2.2  
> **LTS：否**  
> 兼容：相对 2.2 为 MINOR。默认配置打开 2.2 库，行为与 LTS-2 一致。新存储格式默认关闭  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)

## 1. 目标

LTS-2 已经能当单机生产库。本版在不改变默认路径的前提下，补设计里的存储与扩展：

1. **列存 / hybrid**：按表开启。写路径仍先落 WAL；列存可异步重建。投影查询跳过无用列，并有与文档模式的结果等价测试。  
2. **热 / 温 / 冷**：后台迁移，不阻塞写。冷层可接到存储插件。1.8 的 `tiering` 实验旗标在迁移指南里说明如何对应到新布局。  
3. **智能压缩**：数值差分、低基数字典、RLE、通用 gzip。块头记录算法。与加密叠加可测。  
4. **索引合并**：分段压缩合并后查询结果不变，reopen 仍可用。  
5. **大缓存值压缩**；热页预取有命中计数，失败时退回按需读页。  
6. **插件**：`index` / `storage` / `compression` / `backup` / `queryLanguage`。注册校验名称与版本；插件抛错不拖垮引擎。vector 与 S3 只做可调用的 stub，可用实现分别在 3.3 与 3.1。  
7. **大结果 chunk 执行**，结果与非 chunk 等价。  
8. **GeoIndex、中文分词**：可选。缺少分词依赖时引擎仍能 open。  
9. **savepoint** 不在本版；放到 2.4 的事务模型里一起做。

### 成功标准

- 默认关闭列存与插件时，FT-V22 回归绿。  
- 开启列存的表：投影结果正确，且有可重复的读页或耗时对比。  
- 插件异常被隔离。  
- FT-V23-* 全绿。发布说明写明 **非 LTS**，建议生产仍 pin 2.2，除非需要本版存储格式。

### 不做

多写者、复制、GraphQL、Raft、WASM、可用向量检索。

## 4. 与 LTS 的关系

2.2 用户不升级也能继续得到安全补丁。升级到 2.3 是为了列存或插件，不是为了「更稳定」。多写者稳定线是 **2.5**。
