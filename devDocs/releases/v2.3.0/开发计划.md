# JSONSQLite v2.3.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**存储与查询增强**（列存、分层、压缩、插件）  
> 前置：**2.2.0 LTS-2 已宣布**。生产默认 pin 继续是 2.2  
> **LTS：否**  
> 兼容：相对 2.2 为 MINOR。默认配置打开 2.2 库，行为与 LTS-2 一致。新存储格式默认关闭  
> 路线图：[../ROADMAP.md](../ROADMAP.md) · 矩阵：[../FEATURE-MATRIX.md](../FEATURE-MATRIX.md)

---

## 1. 目标

LTS-2 已经能当单机生产库。本版在不改变默认路径的前提下，补设计里的存储与扩展：

1. **列存 / hybrid**：按表开启。写路径仍先落 WAL；列存可异步重建。投影查询跳过无用列，并有与文档模式的结果等价测试。  
2. **热 / 温 / 冷**：后台迁移，不阻塞写。冷层可接到存储插件。1.8 的 `tiering` 实验旗标在迁移指南里说明如何对应到新布局。  
3. **智能压缩**：数值差分、低基数字典、RLE、通用 gzip。块头记录算法。与加密叠加可测。  
4. **索引合并**：分段压缩合并后查询结果不变，reopen 仍可用。  
5. **大缓存值压缩**；热页预取有命中计数，失败时退回按需读页。  
6. **插件**：`index` / `storage` / `compression` / `backup` / `queryLanguage`。注册校验名称与版本；插件抛错不拖垮引擎。vector 与 S3 只做可调用的 stub，可用实现分别在 3.3 与 3.1。  
7. **大结果 chunk 执行**，结果与非 chunk 等价。  
8. **GeoIndex、中文分词**：可选。缺少分词依赖时引擎仍能 open。  
9. **savepoint** 不在本版；放到 2.4 的事务模型里一起做。

### 成功标准

- 默认关闭列存与插件时，FT-V22 回归绿。  
- 开启列存的表：投影结果正确，且有可重复的读页或耗时对比。  
- 插件异常被隔离。  
- FT-V23-* 全绿。发布说明写明 **非 LTS**，建议生产仍 pin 2.2，除非需要本版存储格式。

### 不做

多写者、复制、GraphQL、Raft、WASM、可用向量检索。

## 3. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。这是安装包读者的说明。只改版本号、或只链到 `API.md` / `CLI-API.md`，都不算完成。

写作要求：

- 与已实现且验收通过的默认行为、API、CLI 一致。默认关闭的能力写成 opt-in，并给出打开方式。未交付的能力（含 vector / S3 的可用实现、savepoint）不得写成已支持。
- 读者不打开本计划，也要能判断：默认会不会改变 2.2 库的行为、新存储格式怎么开、开了之后怎么调用、失败时引擎还能否查询。
- 示例使用真实导出与 `jsonsqlite` 命令，可复制。默认值与实现一致。
- 文首写明 **2.3.0、非 LTS**，以及生产仍应 pin **2.2**，除非需要本版存储格式。

本版 README 必须写清：

1. 默认路径：不改配置即可打开 2.2 库，行为与 LTS-2 一致。列存、分层、插件默认关闭。用对照说明「什么都不开」和「按表打开列存」分别发生什么。
2. 列存 / hybrid：按表开启的配置或 API。写路径仍先落 WAL，列存可异步重建。投影查询如何跳过无用列。写明与文档模式的结果等价，以及读者能在哪里看到读页或耗时对比（测试名或文档锚点；没有实测数字就不要编）。
3. 热 / 温 / 冷：后台迁移不阻塞写。冷层如何接到存储插件。1.8 的 `tiering` 实验旗标如何对应到新布局，按迁移指南里的对应关系写成可执行步骤。
4. 智能压缩：数值差分、低基数字典、RLE、通用 gzip 各自在什么数据上使用、如何选择。块头记录算法，reopen 后如何识别。与加密叠加时的顺序，以及 round-trip 失败时调用方看到什么。
5. 索引合并：`index compact` 的命令示例。合并后查询结果不变，reopen 仍可用。写明合并的是分段，不是删索引。
6. 缓存：大缓存值压缩的开启方式。热页预取的命中计数在哪里读。预取失败时退回按需读页，写明退回不是错误。
7. 插件：`index` / `storage` / `compression` / `backup` / `queryLanguage` 的注册方式、名称与版本校验失败时的结果。插件抛错后引擎仍可继续查询，给一个隔离后的调用示例。vector 与 S3 写明只是可调用的 stub，可用实现分别在 3.3 与 3.1。
8. 大结果 chunk 执行：何时走 chunk，结果如何与非 chunk 等价。不要只写「支持 chunk」。
9. GeoIndex、中文分词：可选启用方式。缺少分词依赖时 `open` 仍然成功，写明缺的是哪一类依赖、open 之后分词查询不可用而其余查询可用。
10. CLI 示例：`plugin list`、`plugin info`、`index create --type geo`、`index compact`。写明 2.2 稳定命令的语义不变。
11. 明确不在本版：savepoint（在 2.4）、多写者、复制、GraphQL、Raft、WASM、可用向量检索。

## 5. 与 LTS 的关系

2.2 用户不升级也能继续得到安全补丁。升级到 2.3 是为了列存或插件，不是为了「更稳定」。多写者稳定线是 **2.5**。
