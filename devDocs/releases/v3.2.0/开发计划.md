# JSONSQLite v3.2.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**异步复制长期稳定线（LTS-4）**  
> 前置：**3.1.0** Quorum、读写分离、冷存储故障隔离已绿并完成浸泡  
> **LTS：是 —— LTS-4**  
> 兼容：相对 3.1 为 MINOR，**本版不增加功能**。复制默认仍然关闭  
> 路线图：[../ROADMAP.md](../ROADMAP.md)

---

## 1. 为什么 3.2 可以当 LTS

复制的行为在 3.0 首次出现，在 3.1 补上 Quorum 和路由。3.2 不再改这些语义，只冻结。

适合 pin 本线的人：需要异步主从、接受手动提升、不要求自动选主。  
不适合：把本版当成强一致集群。自动选主与分片在 3.4，且 **3.4 禁止宣布 LTS**。

承诺：

- 不开启复制时，单机正确性不低于 LTS-3 的默认单写者模式。  
- 已文档化的滞后、Quorum 失败、读路由策略、手动 promote，在 `3.2.x` PATCH 中不缩小。  
- PATCH 不加入 Raft 或 `cluster` 命令。  
- 与 LTS-2、LTS-3 并行。安全补丁按「单机是否受影响」分别评估。

主推荐 tag：只需要单机的项目继续 pin **LTS-2（2.2）**。`lts-4` 单独指向 3.2，不自动取代 `lts`。

## 2. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。3.2 不增加功能，README 要写的是异步复制这条线被冻结之后，谁该 pin、默认关复制时行为是什么、哪些语义以后的 PATCH 不能缩小。只改版本号不算完成。

写作要求：

- 不改写 3.0 / 3.1 已经文档化的语义，也不在 README 里预告 Raft、`cluster` 或自动选主。
- 读者要能分清三条 LTS：单机、多写者、异步复制。文首不能把 3.2 写成唯一生产版本。
- `getCompatibilityInfo()` 与 `version --json` 的示例可复制，字段与实现一致。
- 文首写明 **3.2.0、LTS-4**，复制默认仍然关闭，并且没有自动选主。

本版 README 必须写清：

1. 选型：
   - 只需要单机：继续 pin **LTS-2（2.2）**。
   - 需要同一台机器多进程写：pin **LTS-3（2.5）**。
   - 需要异步主从、接受手动提升、不要求自动选主：pin **LTS-4（3.2）**。
   - 需要强一致集群、自动选主或自动分片：不是本版。那些能力在 3.4，且 **3.4 禁止宣布 LTS**。
2. 承诺：不开启复制时，单机正确性不低于 LTS-3 的默认单写者模式。已文档化的滞后、Quorum 失败、读路由策略、手动 promote，在 `3.2.x` PATCH 中不缩小。PATCH 不加入 Raft 或 `cluster` 命令。与 LTS-2、LTS-3 并行；安全补丁按「单机是否受影响」分别评估，README 告诉用户如何对号入座。
3. 复制默认关闭。关闭时的单机示例仍然放在前面。开启复制的步骤保留 3.1 已冻结的 Quorum、读写分离、手动 promote 与审计说明，本版不删这些，也不新增步骤。
4. `getCompatibilityInfo()` 标明 `lts: true`、线 `3.2`。`version --json` 含 `ltsLine: '3.2'`。解释字段，避免和包版本号混用。
5. `replica status` 字段冻结：列出字段表。PATCH 不得在 README 里预告新字段。无 `cluster` 子命令，命令表里不要出现。
6. dist-tag：`lts-4` 指向本线，不自动取代 `lts`。写明不带 tag 的 `npm install` 不会因此改到 3.2。若主推荐仍是单机，`lts` 继续指向 LTS-2。
7. 明确不在本版：新复制语义、自动选主、Raft、自动 rebalance、跨机锁。
