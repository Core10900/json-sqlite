# JSONSQLite v3.2.0 开发计划

> 包名：`@webofcat/jsonsqlite`  
> 主题：**单机运维与体验收口**（时间点恢复、时间旅行保留、调优、数据质量、WebSocket、Admin、性能包络）  
> 前置：**3.1.0** 默认路径回归已绿  
> **LTS：否**。本版收口单机设计，但下一批才进入复制，不能在这里宣布完工  
> 兼容：相对 3.1 为 **MINOR**。默认不开启 Redis、不缩短已有 changelog、不自动修复数据

## 1. 目标

3.1 之后，单机还缺方案里的运维闭环和体验面。本版补这些能力。复制从 3.3 才开始。

1. **PITR**：`restore` 可以停在一个时间戳。顺序是全量备份，再按序应用不晚于该时间的增量。checksum 失败则目标库不变。  
2. **时间旅行**：changelog 默认保留 7 天，配置键 `timeTravelRetentionMs`，与备份 `keepDays` 的裁剪分开。`rollbackToTime` 没有确认参数时拒绝，并写审计。确认后的回滚也写审计。  
3. **AutoTune**：相对基线识别缓存命中、慢查询和压缩收益。可以灰度调整缓存大小和压缩策略。校验失败则回到应用前的配置。默认关闭。自动建索引仍遵守 2.1 的 dry-run 默认。方案里的 `autoIndex` 就是现有 `autoTune`，`autoIndexThreshold` 就是公开配置 `autoTuneMinHits`，默认保持现在的 2，不改成方案示例里的 1000。触发仍是慢查询，不另加会改索引的定时器。  
4. **数据质量**：完整度、唯一性、准确度、一致性、时效性。五项都带分数和建议。建议不写库。`autoFix` 是显式 API，默认不在 open 或定时任务里运行。  
5. **流**：在 `dataChanged` 上组成处理管道，滑动窗口结果经 **WebSocket `/stream`** 推送。同一条连接也推送与现有 SSE 相同的指标事件。现有 SSE 保留。  
6. **Admin** 分页：`/admin`、`/admin/queries`、`/admin/tables`、`/admin/monitor`、`/admin/backup`、`/admin/settings`。查询台展示 3.0 的分段计划和索引选择。  
7. **插件**可从磁盘入口加载。名称和版本校验失败则不注册。入口抛错被隔离，引擎仍可查询。`queryLanguage` 的 `parse` 只能返回引擎已有的 JSON 查询对象，再交给现有执行器；返回别的形状则拒绝，不执行插件代码。vector 与 S3 仍是 stub。  
8. **L3 Redis** 为可选依赖，默认关闭。未安装 Redis 客户端时 `open` 成功，L3 计为关闭。  
9. **Advisor** 记录用户接受或拒绝的建议，下一次只调整排序，不自动改查询、不自动建索引。建议正文和接受/拒绝进入 Monitor，AutoTune 从 Monitor 读，不另建旁路存储。  
10. **性能**：`apps/bench` 增加 100 万文档的点查、10 万级过滤、10 万条批量写入，以及方案 §12.3 的范围、全文、并发读写。公布本机包络。方案 §1.3 是目标；达不到的项写进 Release，不改测试去凑数字。  
11. CI 增加 fast-check（或同等属性测试）：随机文档与随机过滤，索引路径与全表过滤等价。Clinic.js 脚本放在 `apps/bench`，不进入发布包依赖。  
12. **Delta**：新写入只记录操作和变更字段，不重复存整篇未改文档。同一集合的 delta 达到 1000 条（可配置）时生成快照，快照带 checksum；快照成功之后才按 7 天保留窗删除更旧的 delta。快照校验失败则不删旧 delta。  
13. 磁盘满或目标路径无写权限时，本次写入失败并返回稳定错误。失败前已经提交的文档仍可打开。不把未完成的写入报成成功。  
14. 本版新增的 `l3` / `redis` 配置进入 `config.example.json`，并从危险键列表移除。缺客户端时这些键表示关闭，不使 `open` 失败。未在本版实现的 `replica`、`cluster`、`graphql`、`wasm` 仍拒绝。  
15. 发布 `exports["./plugin"]`，只含插件契约类型和注册辅助函数。深路径 `dist/` 仍不是公共 API。  
16. **指标**：`getMetrics()` 在现有累计次数之外给出窗口 QPS、近期查询的 p50/p95/p99、错误率、各集合 WAL 文件字节、表文档数和索引数。`writers: 'multi'` 时累计锁等待毫秒；单写者为 0。告警增加 `response_time`，用 p99 与 `alerts.responseTimeMs` 比较。已有的缓存命中和错误率规则保留。`/health` 增加内存字节和当前锁数量。`memoryWatermarkBytes` 默认 0，只报告不因此把状态打成 degraded；大于 0 且堆超过它时为 degraded。复制角色仍留到 3.3，复制关闭时健康检查不因此失败。  
17. **事务超时**：扁平键 `transactionTimeoutMs`，默认 `0`（关闭）。大于 0 时，超时的事务回滚并返回稳定错误，不提交部分写入。默认 0 不改变现有短事务。  
18. 不采用方案 §9 的嵌套配置对象。2.2 已冻结扁平字段，嵌套的 `cache` 继续拒绝。本版只增加上面的扁平键。`syncMode: 'full'` 即方案里的 fsync，不另加 `sync: "fsync"`，也不加 `sync: "batch"` 或 `checkpointInterval`。加密密钥环境变量维持 `JSONSQLITE_KEY`。  
19. **库事件**：在现有 `ready`、`dataChanged` 之外发出 `metrics`。间隔键 `metricsIntervalMs`，默认 5000，与现在 SSE 的推送间隔一致。`error` 只在已有监听器时发出；没有监听器时只计入错误数，不用未处理的 `error` 事件把进程打崩。

### 成功标准

- 默认配置通过 3.1 回归。  
- PITR 停在时间戳的测试：该时间之后的变更不在恢复结果里，该时间及之前的已提交变更在。  
- 未确认的 `rollbackToTime` 不改数据。  
- Admin 六个路径可打开，查询台能看到分段耗时。  
- 100 万文档包络写入 `devDocs/releases/v3.2.0/性能包络.md`。  
- FT-V32-* 全绿。Release 标明 **非 LTS**，并写明本版不是设计完工版。

### 不做

异步复制、Quorum、自动选主、GraphQL、连接池、多库注册表、可用向量检索、可用 S3、Raft、WASM。

## 3. 文档交付：同步更新 `packages/core/README.md`

本版开发完成、勾选验收之前，必须在同一次交付里更新 [`packages/core/README.md`](../../../packages/core/README.md)。只改版本号、或把时间旅行写成无限保留，都不算完成。

写作要求：

- 说明文字用中文。本版改到的 `packages/core/README.md` 与仓库根 `README.md` 都用中文写。命令、配置键、错误码和代码示例保持原文。用英文段落代替中文说明不算完成。
- 与确认旗标、审计字段、Redis 缺席时的 open 结果、性能包络文件一致。
- 读者要能完成一次 PITR、一次被拒绝的回滚、一次打开 Admin 查询台。
- 示例可复制。性能数字只引用 `性能包络.md`，不在 README 里另写一套。
- 文首写明 **3.2.0、非 LTS**，并写明设计完工线是 **3.6**。

本版 README 必须写清：

1. PITR 的命令和 API。时间戳的单位。该时间之后的写入不在恢复结果中。checksum 失败时目标目录不变，写明错误码。
2. changelog 默认保留 7 天的配置名。它和 `keepDays` 各管什么。过期变更被裁掉之后，更早的 `queryAtTime` 返回什么。
3. `rollbackToTime` / `rollback --to`：没有确认时的错误，确认后的审计字段（操作、集合、时间戳、调用方）。
4. AutoTune 默认关闭。打开后的灰度步骤，校验失败时配置回到原值。给一条 dry-run 输出里能看到的建议类型。
5. 质量报告的五项名称，以及每项建议不写库。`autoFix` 的显式调用示例，以及 open 不会调用它。
6. WebSocket `/stream` 的一条最小客户端示例，和 SSE 路径仍然可用的说明。写明这条连接上除了窗口结果，还有与 SSE 相同的指标事件。
7. Admin 六个路径各做什么。查询台里分段耗时和选中索引的字段名。生产仍要 token；非本机绑定的要求与 2.0 TLS 门禁相同。
8. `plugin load` 的路径、版本校验失败时的退出码、插件抛错后的下一次查询。
9. Redis：默认关闭的配置，未安装客户端时 open 成功，L3 状态在哪里读。
10. Advisor 接受/拒绝如何记录，这些记录出现在哪个 Monitor 字段。下一次建议不会直接建索引。AutoTune 读的是这份记录。
11. 性能包络文件的路径，以及哪些项达到或未达到方案 §1.3。未达到的句子和 Release 使用同一说法。  
12. Delta 快照阈值、变更字段的形状、checksum 失败时旧 delta 仍在。  
13. 磁盘满和无写权限的错误码。  
14. `l3` 配置示例，以及没装 Redis 客户端时的结果。`replica` 等仍未实现的键继续被 `config validate` 拒绝。  
15. `import '@webofcat/jsonsqlite/plugin'` 能拿到的符号列表。  
16. 指标字段：QPS 的窗口、p50/p95/p99、锁等待（单写者为 0）、WAL 字节、表文档数和索引数。`response_time` 告警的配置名和比较的是 p99。`/health` 里的内存字节、锁数量，以及 `memoryWatermarkBytes` 默认 0 时不改变健康状态。  
17. `transactionTimeoutMs` 默认 0。大于 0 时超时回滚的错误码，以及已提交的上一笔事务仍在。  
18. 配置保持扁平。给出 `timeTravelRetentionMs`、`transactionTimeoutMs`、`alerts.responseTimeMs`、`autoTuneMinHits`、`metricsIntervalMs` 的示例。写明 `autoIndex` 就是 `autoTune`。不接受嵌套的 `cache` 对象，不加 `sync: "batch"` 和 `checkpointInterval`。`syncMode: 'full'` 对应 fsync。  
19. `metrics` 事件的间隔和载荷。没有 `error` 监听器时进程不崩。  
20. 明确不在本版：复制、Quorum、GraphQL、多库、可用向量、可用 S3、Raft、WASM、HTTP 文档 REST（在 3.4）。

## 5. 风险

| 风险 | 缓解 |
|------|------|
| 自动调优改坏缓存 | 默认关；失败回滚是门禁 |
| PITR 与时间旅行两套时间源不一致 | 文档写明一个用备份链，一个用 changelog |
| 百万文档测试过慢拖垮每次 CI | 全量包络在发版任务；CI 继续相对回归加小样本属性测试 |
