# JSONSQLite v3.2.0 性能包络

> 机器：本机发版跑数 · Node.js ≥ 20 · `syncMode: 'none'` · 非 LTS  
> 方案 §1.3 是目标；达不到的项在表里标明，不改测试去凑数字。  
> 数字只写在本文件。安装包 README 引用本路径，不另写一套。

## 运行说明

发版任务在 `apps/bench` 上扩大样本：

```bash
BENCH_N=1000000 pnpm --filter @jsonsqlite/bench start
```

大样本使用事务分块批量写入、更大 `pageSize` / `maxResidentDocs`，并跳过整库 `rebuildIndexes`（不是 §1.3 场景）。若发版机上百万文档过慢，可先用 `BENCH_N=100000` 核对路径，再在发版窗口跑满 100 万。

## 实测（100 万文档量级）

| 场景 | 实测 | §1.3 目标 | 是否达到 |
|------|------|-----------|----------|
| 点查（按 `_id` / 等值索引） | 均值 **5.72 ms** | 亚毫秒级均值 | **未达到** |
| 10 万级过滤（`age` 树索引，约 10 万命中） | **8211 ms** | 可接受交互延迟 | **未达到**（秒级） |
| 10 万条批量写入 | **521 ms** | 可完成且不崩 | **达到** |
| 范围查询（tree，`age` 10–20） | **9419 ms** | 优于全表扫描 | **达到**（相对扫描；绝对值秒级） |
| 全文（inverted `$contains`） | **231 ms** | 可用 | **达到**（功能可用） |
| 并发读写 | **41 ms**（20 读 + 20 写） | 单机不崩溃 | **达到** |
