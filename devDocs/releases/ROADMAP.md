## 1. 什么样的版本可以当长期稳定版

四条同时满足才可以宣布 LTS：

1. **本版不引入新子系统。** 分页、多写者、复制、选主都必须先在前一版落地并浸泡。  
2. **该契约下的正确性红线全绿**：已提交崩溃可恢复，`_version` 单调，提交后索引与数据一致，备份校验失败则拒绝恢复。多写者或复制的 LTS 还要加上各自的故障注入。  
3. **宣布之后 PATCH 只做安全与正确性。** 不新增命令，不改默认行为，不升格式，除非安全修复且可迁移。  
4. **相对上一档相关 LTS 有迁移指南。**

做不到第 1 条的版本一律是浸泡或功能列车，Release 必须写非 LTS。

| 代号 | 版本 | 能否作为 LTS | 适合谁 |
|------|------|----------------|--------|
| **LTS-1** | **1.6.x** | 已经是 | 继续使用旧的单写者契约 |
| — | 1.7 / 1.8 | 否 | 已交付的体验与性能预备 |
| — | **2.0 / 2.1** | 否 | 单机正确性与运维闭环的浸泡 |
| **LTS-2** | **2.2.x** | **可以，且是新项目的主推荐 pin** | 单写者、分页存储、诚实的 RC/RR、备份能恢复 |
| — | **2.3** | 否 | 列存、分层、插件；默认路径须兼容 LTS-2 |
| — | **2.4** | 否 | 多写者第一次实现 |
| **LTS-3** | **2.5.x** | 可以 | 需要单机多进程写的人。默认仍是单写者 |
| — | **3.0 / 3.1** | 否 | 异步复制雏形与硬化 |
| **LTS-4** | **3.2.x** | 可以 | 需要异步主从、接受手动提升、不要自动选主 |
| — | **3.3** | 否 | GraphQL、连接池、多库、向量可用插件 |
| — | **3.4** | **不可以** | 集群实验。即使混沌全绿，也要另开后续版本浸泡后才讨论下一档 LTS |

主推荐 tag `lts` 指向 **LTS-2（2.2）**。`lts-3`、`lts-4` 是按需的附加线，不自动抢走主推荐。只需要嵌入式单写者的后端不要为了集群升级。

```text
1.6 LTS-1  ●━━━━━━━━━━━━━━━━━━━━━━（窗口至 LTS-2 之后，见 Release）
1.7–1.8    ··已交付··
2.0–2.1         ··正确性浸泡··
2.2 LTS-2            ●━━━━━━━━━━━━━━━━→ 主推荐生产 pin
2.3                     ··存储增强··
2.4                        ··多写者浸泡··
2.5 LTS-3                     ●━━━━━━→ 需要多写者才 pin
3.0–3.1                          ··复制浸泡··
3.2 LTS-4                           ●━━→ 需要异步复制才 pin
3.3                                    ··适配器··
3.4                                       ··集群实验，禁止 LTS··
```

## 2. 生产级与「设计功能做完」是两件事

**生产级（现在就以它为发版顺序）**：单机可恢复、备份校验、隔离级别与实现一致、数据量不受整表进内存约束、损坏可见。这是 LTS-2 的定义。

**设计采纳**：列存、插件、Geo、复制、GraphQL、集群实验按上表往后排。集群实验失败不推翻 LTS-2。方案 §1.2 排除的完整 SQL、替代 Elasticsearch / ClickHouse、强制外部 LLM，继续排除。

方案 §12.3 的绝对毫秒数只作方向。2.0 公布 §12.3 六个场景的实测包络，CI 守相对回归。

## 4. 维护

| 线 | 节奏 |
|----|------|
| LTS-1 `1.6.x` | 安全与正确性，直到 Release 宣布的窗口结束 |
| LTS-2 `2.2.x` | 主推荐。PATCH 不加功能 |
| LTS-3 `2.5.x` | 仅多写者用户。与 LTS-2 重叠 |
| LTS-4 `3.2.x` | 仅异步复制用户。不含选主 |
| 2.0→2.1、2.4、3.0→3.1 | 浸泡，只修阻断缺陷直到下一档 LTS |
| 3.4 | 默认关闭。不进入 `lts*` tag |
