# JSONSQLite 版本路线图

> 基准日期：2026-11-05（重排 3.x；2.x 已交付线不变）  
> 当前代码线：`@webofcat/jsonsqlite@2.5.0`（**LTS-3**，默认单写者）。在 **3.6.0** 宣布之前，生产 pin 仍是 **LTS-2 = 2.2.x**；需要多写者才 pin **LTS-3**  
> 已宣布的长期稳定线：**LTS-1 = 1.6.x**、**LTS-2 = 2.2.x**、**LTS-3 = 2.5.x**  
> 计划中的完工线：**LTS-4 = 3.6.x**。3.6 之前没有 3.x 的 LTS  
> 2026-11-05 删除原 `v3.0.0`–`v3.4.0` 计划目录。已发布的 1.7 / 1.8 / 2.0 正文里若仍把 3.2 写成 LTS-4、或把 3.4 写成集群实验的终点，以本文件为准  
> 能力对照：[FEATURE-MATRIX.md](./FEATURE-MATRIX.md)  
> 设计依据：`devDocs/design/`。生产红线以《技术实现方案》§12.2、§13 为准

## 1. 什么样的版本可以当长期稳定版

四条同时满足才可以宣布 LTS：

1. **本版不引入新子系统。** 分页、多写者、复制、选主都必须先在前一版落地并浸泡。  
2. **该契约下的正确性红线全绿**：已提交崩溃可恢复，`_version` 单调，提交后索引与数据一致，备份校验失败则拒绝恢复。多写者、复制或集群的 LTS 还要加上各自的故障注入。  
3. **宣布之后 PATCH 只做安全与正确性。** 不新增命令，不改默认行为，不升格式，除非安全修复且可迁移。  
4. **相对上一档相关 LTS 有迁移指南。**

做不到第 1 条的版本一律是浸泡或功能列车，Release 必须写非 LTS。

| 代号 | 版本 | 能否作为 LTS | 适合谁 |
|------|------|----------------|--------|
| **LTS-1** | **1.6.x** | 已经是 | 继续使用旧的单写者契约 |
| — | 1.7 / 1.8 | 否 | 已交付的体验与性能预备 |
| — | **2.0 / 2.1** | 否 | 单机正确性与运维闭环的浸泡 |
| **LTS-2** | **2.2.x** | **可以，且在 3.6 宣布前是新项目的主推荐 pin** | 单写者、分页存储、诚实的 RC/RR、备份能恢复 |
| — | **2.3** | 否 | 列存、分层、插件；默认路径须兼容 LTS-2 |
| — | **2.4** | 否 | 多写者第一次实现 |
| **LTS-3** | **2.5.x** | 可以 | 需要单机多进程写的人。默认仍是单写者 |
| — | **3.0–3.5** | 否 | 设计补齐、复制、接入层、集群浸泡。默认不改变 2.5 的单写者行为 |
| **LTS-4** | **3.6.x** | **可以，且是设计功能完工后的长期稳定线** | 需要方案里已排期的全部能力。默认仍是单写者，复制和集群关闭 |

`3.7` 及以后不在本路线里。设计排期的未完成项必须落在 `3.0.0`–`3.5.x`，由 `3.6.0` 冻结。

3.6 宣布之前，主推荐 tag `lts` 继续指向 **LTS-2（2.2）**。宣布 3.6 时，`lts` 改指向 **3.6**；`lts-2`、`lts-3` 保留。`lts-4` 只指向 3.6。升级到 3.6 不会自动打开多写者、复制或集群。

```text
1.6 LTS-1  ●━━━━━━━━━━━━━━━━━━━━━━（窗口至 LTS-2 之后，见 Release）
1.7–1.8    ··已交付··
2.0–2.1         ··正确性浸泡··
2.2 LTS-2            ●━━━━━━━━━━━━━━━━→ 3.6 宣布前的主推荐
2.3–2.4                 ··存储增强 / 多写者浸泡··
2.5 LTS-3                     ●━━━━━━→ 需要多写者才 pin
3.0–3.2                          ··单机设计补齐··
3.3–3.4                             ··复制与接入··
3.5                                    ··集群浸泡，禁止 LTS··
3.6 LTS-4                                 ●━━→ 设计完工后的长期稳定线
```

## 2. 未完成项的优先级

排序依据：读路径先可信，再换索引和存储算法，然后补单机运维；复制依赖已经能恢复的单机；接入层不改存储契约；选主和自动分片放在最后一个功能版，并留一个只修缺陷的版本再冻结。

| 优先级 | 版本 | 为什么在这一档 |
|--------|------|----------------|
| 1 | **3.0.0** | 查询过滤、取消、代价计划和分段剖析。后面的索引、列存和复制都读这条路径 |
| 2 | **3.1.0** | B+Tree、空间索引、列编码、hybrid、压缩选算法、分层压缩。默认关闭，不改 2.5 库的打开结果 |
| 3 | **3.2.0** | 时间点恢复、时间旅行保留、调优、质量、WebSocket、Admin 分页、百万文档包络。单机设计在这里收口 |
| 4 | **3.3.0** | 异步主从。先做到从库最终可见、不自动选主。分片路由只做默认关闭的原型 |
| 5 | **3.4.0** | 复制硬化（Quorum、读写分离、可用冷存储）与接入层（GraphQL、连接池、多库、向量可用实现）并行。仍然没有选主 |
| 6 | **3.5.0** | 选主、自动分片、跨机锁、只读 WASM 实验包（必交付）。混沌三项全绿才允许发版。`3.5.x` 只修缺陷 |
| 7 | **3.6.0** | 不加功能。冻结 3.5 已经跑绿的契约，宣布 **LTS-4** |

每个功能版的修复版本（`3.0.1`、`3.1.1`……）只做正确性和安全，不新增命令、不改默认值。新能力进下一个 minor。

### 维持不做

这些项出现在大纲或对照文档里，但不排进 3.x。做进去会让 3.6 无法冻结。

| 项 | 原因 |
|----|------|
| 完整 SQLite SQL 方言 | 3.0 只扩大已有子集：单字段 `GROUP BY` 的 count/sum/avg/min/max，以及指出不支持的语法。不实现 SQLite 的全部语句 |
| 替代 Elasticsearch | 倒排保持检索能力；3.4 的向量插件写明不是通用向量库 |
| 替代 ClickHouse | 3.1 的列存只做投影和聚合加速，WAL 仍是提交事实 |
| 核心包依赖 Express / Nest | 3.4 只交付示例或独立包 |
| 多语言 TCP 协议 | 3.4 的 `serve` 只把现有 HTTP/Admin 跑成常驻进程，不新增线协议 |
| `READ_UNCOMMITTED` | 方案 §7.2 把它写成仅调试的脏读。2.0 起对未实现的隔离级别直接拒绝，3.x 不改回脏读 |
| L2 mmap | 方案允许 L2 与 L1 合并成进程内两档。不单做 mmap |
| 校验和改为 CRC32 或 BLAKE3 | 已发布的 WAL 与备份链使用 SHA256。更换算法会打断 2.x 恢复，3.x 不换 |
| 方案 §9 的嵌套配置对象 | 2.2 已冻结扁平字段。3.x 只加等价扁平键（如 `timeTravelRetentionMs`），继续拒绝嵌套的 `cache` |
| WAL 段轮转、`sync: "batch"`、`checkpointInterval` | 每次持久写入已经 checkpoint 并截断 WAL。不把立即刷盘改成按条数、超时或 30 秒合并 |
| 索引删除改为标记后后台清理 | 同步删除已经让索引立即不可用，查询不再使用它 |
| `_id` 改成 ULID 或 UUID | 现有主键是时间前缀加随机串，唯一性已经满足。不改变新文档的 id 形状 |

## 3. 生产级与「设计功能做完」

**现在就能 pin 的生产级 = LTS-2（2.2）**：单写者、分页、备份链可恢复、WAL 失败关闭、RC 与 RR 诚实。需要同一台机器多进程写，pin **LTS-3（2.5）**。

**设计完工 = LTS-4（3.6）**：3.0–3.5 的能力都已交付且默认关闭的开关不会在升级时自己打开。3.6 的 PATCH 不再加入复制语义、选主或新命令。

方案 §12.3 的绝对毫秒数仍是方向。3.2 用 100 万文档跑 §1.3 的三个单机目标，并公布 §12.3 六个场景。达不到的数字写进该版 Release，3.6 冻结的是公布过的包络，不回写大纲里的宣传数字。

## 5. 维护

| 线 | 节奏 |
|----|------|
| LTS-1 `1.6.x` | 安全与正确性，直到 Release 宣布的窗口结束 |
| LTS-2 `2.2.x` | 3.6 宣布前的主推荐。PATCH 不加功能 |
| LTS-3 `2.5.x` | 仅多写者用户。与 LTS-2 重叠 |
| 3.0–3.4 | 功能列车。各自的 PATCH 不加命令 |
| 3.5.x | 集群浸泡。只修阻断缺陷，直到 3.6 |
| LTS-4 `3.6.x` | 设计完工线。PATCH 不加功能、不升格式、不改默认开关 |
