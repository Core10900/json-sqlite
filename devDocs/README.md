# JSONSQLite 内部文档（devDocs）

本目录存放设计方案、版本开发计划与功能测试计划。按 **主题** 与 **版本** 分类，便于后续扩展 v2.0 等。

## 目录结构

```text
devDocs/
├── README.md                 ← 本说明
├── design/                   ← 跨版本设计（长期有效）
│   ├── JSONSQLite 技术实现方案与计划.md
│   ├── JSONSQLite 生产级实现大纲.md
│   ├── JSONSQLite vs SQLite - 超越的可能性.md
│   └── JSONSQLite npm包与后端接入说明.md
└── releases/                 ← 按版本的开发 / 测试计划
    ├── v1.0/
    │   ├── 开发计划.md
    │   └── 功能测试计划.md
    ├── v1.1.0/
    │   ├── 开发计划.md
    │   └── 功能测试计划.md
    ├── v1.2.0/
    │   ├── 开发计划.md
    │   └── 功能测试计划.md
    ├── v1.3.0/
    │   ├── 开发计划.md
    │   └── 功能测试计划.md
    ├── v1.4.0/
    │   ├── 开发计划.md
    │   └── 功能测试计划.md
    └── v2.0/                 ← 后续版本（按需新建）
        ├── 开发计划.md
        └── 功能测试计划.md
```

## 分类约定

| 目录 | 放什么 | 何时新增 |
|------|--------|----------|
| `design/` | 架构、对标分析、包契约、生产大纲等跨版本文档 | 方案演进时更新或增补 |
| `releases/<version>/` | 该版本的 **开发计划**、**功能测试计划**（及可选复盘） | 每个 minor/major 发版前新建目录 |

## 新增版本文档（示例：v2.0）

```bash
mkdir -p devDocs/releases/v2.0
# 编写：
#   devDocs/releases/v2.0/开发计划.md
#   devDocs/releases/v2.0/功能测试计划.md
```

建议在 `开发计划.md` 中写清需求摘要、任务分解、验收标准；在 `功能测试计划.md` 中用稳定用例 ID（如 `FT-V20-xxx`）。
