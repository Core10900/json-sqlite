# JSONSQLite v1.0 详细开发计划

> 版本目标：`@jsonsqlite/core@1.0.0`  
> 依据：《技术实现方案与计划》《npm包与后端接入说明》  
> 范围：**P0–P4**（P5 分布式/列存扩展不在 v1.0 必达范围）  
> 技术栈：Node.js ≥ 20 · TypeScript · pnpm · Vitest · tsup

---

## 1. v1.0 交付定义

### 1.1 必须交付（Must）

| 编号 | 能力 | 说明 |
|------|------|------|
| M1 | npm 可安装库 | ESM + CJS + `.d.ts`；`open` / `close` 生命周期 |
| M2 | 文档 CRUD | collection + insert/update/delete/upsert/find |
| M3 | WAL + 崩溃恢复 | 已提交数据可恢复；未提交不落库 |
| M4 | 基础事务 | begin/commit/rollback；默认 READ_COMMITTED |
| M5 | 单写者文件锁 | 同路径第二进程打开失败并明确报错 |
| M6 | JSON Query | filter / projection / orderBy / limit / offset |
| M7 | 索引（等值+范围+全文基础） | ObjectIndex / TreeIndex / InvertedIndex |
| M8 | L1 查询缓存 | 写路径失效 |
| M9 | 聚合管道基础 | match / group / sort / limit / project |
| M10 | 备份与 PITR | full + incremental + 时间点恢复 |
| M11 | 监控与健康检查 | 指标、慢查询、`health()` |
| M12 | CLI | `jsql`：query / backup / restore / doctor |
| M13 | HTTP Admin API | localhost + Token；可选简易管理页 |
| M14 | TimeTravel + QueryAdvisor | 历史查询/diff；索引与结构建议 |
| M15 | 包文档 | packages/core README：安装、示例、限制 |

### 1.2 明确不做（v1.0 Out of Scope）

- 多机 Raft / 强一致分片（P5）
- 完整 SQLite SQL 方言
- 浏览器 WASM 引擎
- 强制 Redis / 原生 addon
- 自动调优默认开启（可实现但默认关）

### 1.3 发布节奏

| 标签 | 对应开发阶段 | 说明 |
|------|--------------|------|
| `0.1.0-alpha` | P0+P1 完成 | 可本地/试用安装 |
| `0.2.0` | P2 | 索引与性能 |
| `0.3.0` | P3 | 生产候选 |
| `1.0.0` | P4 核心体验合并 + 稳定 | API + 磁盘 formatVersion 承诺 |

## 2. 阶段总览

| 阶段 | 周期（建议） | 目标 | 出口标准 |
|------|--------------|------|----------|
| **P0 工程基线** | 3–5 天 | 可 build / test / pack | pack 冒烟通过 |
| **P1 MVP** | 2–3 周 | CRUD + WAL + 事务 + JSON Query | 崩溃恢复测试绿；示例可跑 |
| **P2 性能** | 2–3 周 | 索引 + 缓存 + 聚合 + bench | 10 万级指标达标 |
| **P3 生产加固** | 2–3 周 | 备份/监控/CLI/HTTP/加密 | 备份演练 + health |
| **P4 体验** | 2–3 周 | Admin / Advisor / TimeTravel | 演示脚本通过 |
| **稳定与发布** | 1 周 | 文档、CHANGELOG、回归 | 打 `v1.0.0` |

合计约 **10–14 周**（单人全职可参考；可按人力伸缩）。

## 3. 分阶段任务分解

## 4. 目录与模块落地顺序

```
packages/core/src/
  index.ts                 ← P0
  engine/JSONSQLite.ts     ← P0→P1 持续充实
  config/                  ← P0
  errors.ts                ← P0
  types/                   ← P0
  storage/                 ← P1（Catalog, DocumentStore, Wal, FileLock）
  query/                   ← P1→P2
  transaction/             ← P1→P3
  index/                   ← P2
  cache/                   ← P2
  backup/                  ← P3
  monitor/                 ← P3
  api/                     ← P3–P4
  features/                ← P4
```

P0 ──────────────────────────────►
